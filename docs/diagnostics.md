# 诊断与问题反馈

先记录游戏 build、Mwah 版本与构建渠道、是否启用 VNPE，以及出现现象的操作顺序。正常表现和未覆盖路径分别记录；不要先把其他模组的警告归到 Mwah。

## 选择诊断档位

设置 → 参数与杂项 → 诊断档位，默认 **Auto**。

| 档位 | 输出 |
| --- | --- |
| Off | 启动横幅、Warn／Error |
| Auto | Dev 按 Verbose；Steam／GitHub 按 Simple |
| Simple | 结算天意行、退出原因、启动翻译解析信息 |
| Verbose | 再加阶段流水、导演台点选代际、设置保存信息和阶段采样 |

普通日志写入游戏的 `Player.log`，以硬编码英文 `[MWAH] ` 开头。启动横幅给出版本、渠道和启动结果，不受档位限制。Warn／Error 也不被档位静音。

详细档还在游戏 SaveData 目录写 `Mwah-trace.log`：后台每秒采样共享的 A／B 阶段与剩余 tick；文件超过 1 MB 时裁至尾部 800 行。非详细档或尚无有效游戏 tick 时不追加。样本是辅助观测，不是每个 Pawn 的完整事件记录，不能单凭最后一行确定故障归属。

## 按阶段读记录

- `startup OK`：本次初始化完成；用版本和渠道确认安装的是哪一候选。
- `i18n check`：引擎实际解析的按钮与思想标签；结合当前语言判断是否缺文件、注入失效或存在覆盖。
- `fate <scope> ... row=<defName>`：该参与者实际抽到的天意行。配对与物体吻使用不同 scope，机器的普通、研究和营养膏结算也分开记录。
- `kiss begin / kiss perform / thing kiss start`：开始或到达相应阶段，不等于已经完成。
- 走位失败、受击、搭档／目标失效：结合退出原因判断是否为预期取消。未完成的亲吻不发完成奖励；没有结算行本身不证明缺陷。
- `no stage within radius` 后转 Touch：定台未成功后的既有回退，不直接算错误。
- `pick start/ok/end (generation N)`：导演台当跳会话。快速点选会更换代际，关窗应清理它拥有的当前点选。
- `settings saved`：某代设置成功写入。失败时保留待保存状态并重试；规范设置、编辑文本和磁盘结果要分开判断。默认值可不写入设置文件。

## 调用栈、级别与归属分开判断

普通 INFO 也可能附调用栈。紧跟 `[MWAH] note:` 的长栈不是异常证明；先读事件级别和消息，再沿触发顺序检查。WARN 是需要解释的警告，不等于抛出了异常。

`[MWAH]` 或 `Mwah.` 帧可以提供调查线索；缺少它们也不能排除 Def／语言解析等加载错误。缺失类型、Def 或 SoundDef 的归属要核对实际启用组合及引用它的 XML／程序集，不能只看谁出现在公共调用栈中。

零 ERROR／FATAL 是该会话的日志观察，不是功能通过的替代品，也不是要求所有其他模组都无警告。接受一个功能应结合真实交互结果及相关日志；未测功能保留未测。原生崩溃或深度递归可能没有托管异常，不能据此判定某个模组无责。

RimWorld **1.6 使用 Mono 系列运行时，1.7 Waylith 使用 .NET 10**。旧的 Mono 调试器限制不能直接套到 1.7；需要进一步排错时，以实际运行时和转储为准。

## 内容未加载时查哪里

按 **内容源 → LoadFolders 选择 → 实际包 → 消费者** 定位。根共同内容在 `Defs/`、`Languages/`；每个 minor 只选择自己的 DLL；VNPE 登记及专用语言只在条件成立时采用。

自定义列表不会自动追加根或 Common。未列出的旧 Common 目录不会自行生效；仍被选中的根内若残留旧文件，才可能继续加载。升级仍应完整替换模组副本，不叠加覆盖，只启用一个 `coahuilite.mwah`。开发菜单的 Loaded Files For Mod 可查看实际选择，但不证明玩法已经通过。

## 如何交付反馈

提供候选身份、游戏 build、VNPE 启用情况、操作顺序、实际表现和未覆盖项。维护者可指定本地日志供只读检查；进入仓库或公开 issue 的内容先脱敏，不提交原始日志、Pawn 名、坐标、存档标识、个人路径、凭据或工坊发布标识。

安装、游戏操作和实机确认由维护者执行。离线门与实际包检查记录在对应任务；改变布局后只重开受影响的加载结论，复用未改变的玩法证据。

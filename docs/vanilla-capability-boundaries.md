# Vanilla capability boundaries (project reference)

Moved out of `MEMORY.md` on 2026-10-06 during memory compression. Entry names are stable; rulings in `MEMORY.md` cite them as "the 'Who can kiss' table", "the mood ladder entry", etc. Read this file before changing implementation — these are the verified grounds this mod's shape stands on.

## Vanilla capability boundaries (verified against RimSage 1.6 + Odyssey source, 2026-09-02)

Read before changing implementation: these are the grounds this mod's shape stands on.

- **Right-click entry self-registers**: `FloatMenuMakerMap.Init()` reflectively instantiates `typeof(FloatMenuOptionProvider).AllSubclassesNonAbstract()` → a mod provider enters the menu chain with no Def/XML/patch. Base-class gates: `Drafted/Undrafted/Multiselect/RequiresManipulation/MechanoidCanDo/CanSelfTarget/CanTargetDespawned/IgnoreFogged` + `SelectedPawnValid/TargetThingValid/TargetPawnValid/Applies/GetOptionsFor(Thing|Pawn)`.
- **The `SelectedPawnValid` trap**: this mod's override **deliberately skips base** (base would cut everything by the mutant whitelist; mechanism in the last bullet of "Who can kiss"); `MechanoidCanDo => true` is therefore a declared intent, not a capability.
- **Vanilla hard gates (unbypassable at provider level)**: `GetOptions`' first line requires the click inside `Find.CurrentMap`; the `ShouldGenerateFloatMenuForPawn` exclusion list (see the "Who can kiss" table) ⇒ **downed pawns cannot initiate**, but can be targets.
- **Grounds for rejecting the `ability` route**: `PawnComponentsUtility.AddComponentsForSpawn` creates `pawn.abilities` only for `Humanlike || IsMechanoid`; Odyssey's `FleshType.Drone` (`isOrganic=false`) has no `interactions` tracker either. Neither Ability nor `InteractionDef` covers "every pawn" — only a FloatMenu provider does.
- **Approach/facing primitives**: `pather.StartPath(target, PathEndMode.Touch)`, `SocialInteractionUtility.BestInteractableCell/IsGoodPositionForInteraction(≤6 cells + LineOfSight)`, `rotationTracker.FaceTarget(...)`, `GenAdj.AdjacentTo8WayOrInside(Thing,Thing)` (correct for multi-cell bodies). 1.6 **removed `Pawn.CanMove`**; the mobility read is `health.capacities.CapableOf(PawnCapacityDefOf.Moving)` plus the `RaceProps.doesntMove` special case.
- **Map picking uses vanilla `Find.Targeter`; never hand-roll MouseDown in GameComponentOnGUI**: `Targeter.BeginTargeting(...)` brings pointer-following highlight (`GenDraw.DrawTargetHighlight`), mouse attachment (`GenUI.DrawMouseAttachment` + `Widgets.MouseAttachedLabel`), left-click commit, right-click/Esc cancel, and is processed after windows in the map input pipeline — persistent windows (Dev palette) cannot kill the mode the way hand-rolled OnGUI gets killed. `caster: null` ⇒ `ConfirmStillValid`'s "initiator must be selected" check is skipped entirely ⇒ picking works with nothing selected. Two-hop picking chains via consecutive `BeginTargeting` (it resets `needsStopTargetingCall` to false, so starting hop two inside hop one's action survives the following `StopTargeting` — same trick as vanilla `DestinationSelector`). `TargetingParameters.ForPawns()` also selects enemies.
- **A GameComponent must never auto-exit input mode because "some window kind exists"**: `WindowStack.NonImmediateDialogWindowOpen` is true whenever any non-Immediate Dialog-layer window sits in the stack — many mods keep one open permanently, so the director got `End()`-ed on the next event after every `Begin`: "clicking does nothing, not even the prompt bar", while the log showed `director on` repeatedly and `director off` never. Correct: yield by `return` only (never exit the mode), and gate clicks precisely with `WindowStack.GetWindowAt(mousePos)`.
- **Two hard localization facts (settled by the 2026-09-04 translation report)**: the Chinese folder must be named `ChineseSimplified` (matching packages that do display correctly; `SimplifiedChinese` as used by `let_me_gnaw_on_you` is wrong). Inside `DefInjected/<Type>/<file>.xml`, `<LanguageData>`'s children must be **flat dotted keys `DefName.fieldPath`**, not nested def format — `DefInjectionPackage.SetDefFieldAtPath` takes `path.Split('.')[0]` as the defName, so `<MWAH_KissDirector><label>…</label></MWAH_KissDirector>` turns the top name into a bare defName with no field path and silently lands in the report's "missing" section (all four injected files tripped this; the Keyed check cannot see it). List fields use indexes: `MWAH_Kissed.stages.0.label` (313 real mod files do this; the report's printed `stages.kissed_by` is a human suggestion, not writable). `verify-local` now gates it: top names must contain `.` with a real defName prefix. Diagnostic: options menu "save translation report" → desktop `TranslationReport.txt`; "missing" = wrong key format or file unread, "load errors" = type/defName resolution failure.
- **A persistent window must never close input mode or skip drawing**: Dev palette is a non-Immediate Dialog-layer window; "return/End when any dialog exists" leaves the director without its prompt bar during debugging. Correct: draw the prompt unconditionally, yield only for the click landing point (`WindowStack.GetWindowAt(mousePos)`).
- **Facing authority**: `toil.handlingFacing = true` ⇒ `Pawn_RotationTracker.UpdateRotation` early-exits at its very top (skipping even the `job.rotateToFace` and `Drafted` branches); afterwards `rotationTracker.Face/FaceCell/FaceTarget` is the only writer. Vanilla standing chat (`JobDriver_StandAndBeSociallyActive`, `JobDriver_GotoAndStandSociallyActive`) is exactly "handlingFacing + Face every tick + pather.StopDead() every tick" — copy it; `Job` additionally has `lookDirection`/`forceMaintainFacing` for "face one direction only".
- **`GameComponent` requires a `(Game)` constructor**: `Game.FillComponents` calls `Activator.CreateInstance(item2, this)` (this = `Game`). Without it: no compile error, no dialog — one `Could not instantiate a GameComponent of type X: MissingMethodException` line in Player.log and the component silently never runs. The number-one cause of "code written yet totally inert"; check the instantiation contract before adding any component class.
- **Heart fleck**: exactly `FleckMaker.ThrowMetaIcon(cell, map, FleckDefOf.Heart)` (vanilla Lovin uses a 100-tick constant). `Heart` is a **FleckDef** (`Things/Mote/Heart`, `MetaOverlays`); there is no `Mote_Heart`.
- **Two-person lock**: the `JobDriver_Lovin` mirror-job technique (give the partner `StartJob(same def, self, InterruptForced)`); `TryTakeOrderedJob(job, JobTag.Misc)` for courtesy requests like walking home; `Pawn_JobTracker` auto-chains `Wait_MaintainPosture` after a successful job.
- **Mood scaling**: `Thought_Memory.MoodOffset() = stage.baseMoodEffect × moodPowerFactor + moodOffset`; `durationTicksOverride` changes duration per instance; `ThoughtDef.DurationTicks = durationDays × 60000` (1 day = 24 game hours; this mod's durationDays and the "mood duration" factory default are both 1 day and must stay aligned). Vanilla `Pawn_InteractionsTracker.AddInteractionThought` is public static but multiplies by the **other** pawn's `SocialImpact` (and pushes the same value into opinion), gated on `Talking` capacity and the `interactions` tracker → this mod writes its own, using the **own** `SocialImpact`, mood and opinion sharing one multiplier.
- **Non-exploding edge**: `SkillNeed_BaseBonus.ValueFor` returns `1f` when `pawn.skills == null`, and `SocialImpact` is `neverDisabled` → reading the stat on skill-less units is safe.
- **Social-semantics side-effect switch**: `Thought_MemorySocial.Init()` runs inside `ThoughtMaker.MakeThought` and writes `opinionOffset = stage.baseOpinionOffset` → the multiplier must be applied after MakeThought to count; `ShouldDiscard` requires `otherPawn != null && opinionOffset != 0`.
- **Bottom bar extends; the bottom-right toggle strip does not**: `MainButtonDef` is a plain Def (`workerClass/tabWindowClass/order/minimized/buttonVisible/defaultHotKey`) — pure XML adds a bottom-bar button; `MainButtonsRoot.DoButtons()` consults `Worker.Visible` every frame ⇒ overriding `Visible` gives settings-driven show/hide, zero Harmony. But the bottom-right display toggles are **not data-driven**: `PlaySettings.DoMapControls(WidgetRow)` is a wall of hard-coded `row.ToggleableIcon(...)` calls, no Def, no list ⇒ adding one cell would need Harmony (red line, never). Bar order is each Def's `order` (vanilla Architect=1…Factions=90, Mechs=45, Ideos=100, **Menu gear=500**), no grouping; **the last visible button absorbs leftover width**. There is also **no collapse/expand state**: more buttons just narrow (width = screen ÷ visible count, `minimized` takes half); the 1.5 archon ring has zero hits in 1.6 source.
- **Logging infrastructure ceilings**: Player.log has no per-line timestamps, a global 10000-entry Unity cap (afterwards `Debug.unityLogger.logEnabled = false` swallows every `Log.*`), and identical-text folding stops recording at 99 ⇒ every instrument line must carry `t=<tick>` and a unique field. The settings file stores only non-defaults (a diff, not a snapshot); settlement evidence lives in the save XML itself. **Details and trade-offs: `docs/kiss-trace-logging-design-zh.md`.**
- **Unit constants**: `GenTicks.TicksPerRealSecond = 60`, `GenDate.TicksPerDay = 60000` → 1 game hour = 2500 ticks.
- Greyed-item convention: `new FloatMenuOption(label, null, priority…)` (null action = disabled), reason in parentheses inside the label; `FloatMenuUtility.DecoratePrioritizedTask` marks "will preempt"; the ready-made priority is `MenuOptionPriority.InitiateSocial`.

### Mood ladder, nullify lists, SocialImpact anatomy, and the player-HUD surface (re-verified 2026-09-21)

- **Vanilla positive-social mood anchors** (`baseMoodEffect` / duration in game days / opinion; official Simplified-Chinese names read from the installed `Data/Core/Languages/ChineseSimplified (简体中文).tar`, values from `Data/Core/Defs/ThoughtDefs/*.xml`, checked directly on 1.6.4871 rev590 on 2026-09-22): `GotSomeLovin` (简中 **滚床单**) **+8 / 3 days** (opinion +6, stackLimit 10 ×0.6; given directly by `JobDriver_Lovin`, **not multiplied by SocialImpact** — only the `LoveEnhancer` hediff raises `moodPowerFactor` to 1.5) > `KindWordsMood` (简中 **美言**) +5 / 2 days (auto-carried by the `KindWords` social memory's `thoughtToMake`; `KindWords` itself is opinion-only +15/20 days, `showBubble`) > `Nuzzled` (简中 **被亲昵**, rubbed by a bonded animal) +4 / 1 day stackLimit 3 ×0.5, second stage +6 (`stagesStack`, nullified by `Psychopath` + `Inhumanized`) > `AteFineMeal` (简中 **吃了精致食物**) +5 / 1 day. `DeepTalk` (简中 **深入交流**) / `Chitchat` (简中 **闲谈**) are **opinion-only, zero mood** (+15/20 days; chitchat accumulates +0.66 per turn, cap +10) ⇒ in vanilla "being social" is carried by opinion, not mood. `GotMarried` (简中 **和{0}结婚**) +40/30 days is milestone-grade; `AttendedParty` (简中 **参加聚会**) +8/10 days. There is **no** "Got some rest"/"Saw beautiful"/"Social temperature" def (beauty runs through situational thoughts and the `SleptInBedroom` family). ⇒ This mod settled at **+5 / 1 game day / stackLimit 2 ×0.5** (two quick kisses sum ≈ 7.5, still below one lovemakin'), rationale pinned in the comments of `1.6/Defs/Kiss/MWAH_ThoughtDefs.xml`.
- **"These people don't feel this" exists only as nullify lists, never as numeric deltas**: `ThoughtDef.nullifyingTraits` / `nullifyingTraitDegrees` / `neverNullifyIfAnyTrait` / `nullifyingHediffs` / `nullifyingGenes` / `nullifyingPrecepts` / `requiredTraits` / `requiredGenes` / `requiredHediffs` (all XML, zero Harmony). Nullification happens at **read time**: `Thought.MoodOffset()` and `Thought_Memory.MoodOffset()` (`Thought_Memory.cs:168`) both start with `if (ThoughtUtility.ThoughtNullified(pawn, def)) return 0f;`, while `TryGainMemory`'s `CanGetThought(pawn, def)` defaults `checkIfNullified=false` and **still stores** ⇒ the entry exists in memory but is filtered out of `ThoughtHandler.GetAllMoodThoughts` (`MoodOffset() != 0f`) and the opinion grouping, so the panel shows nothing. Vanilla precedents: `Nuzzled` nullifies under `Psychopath`; `KindWordsMood` under `Inhumanized` (`MayRequire` Anomaly). **No vanilla trait or gene adds or subtracts social mood.**
- **`SocialImpact` is vanilla's only "social effect scaling" carrier** (`Defs/Core/Stats/Stats_Pawns_Social.xml`): `defaultBaseValue 1`, `minValue 0.2`, `neverDisabled`; the social skill's `SkillNeed_BaseBonus` is baseValue **0.82** + **0.0275/level** (level 0 = 82% → 10 ≈ 109.5% → 20 = 137%); capacity factors **Talking weight 0.9** (`allowedDefect 0.05`) + **Hearing weight 0.3**; hat `equippedStatOffsets` +10%~20%. Application site: `Pawn_InteractionsTracker.AddInteractionThought` sets `moodPowerFactor = otherPawn.GetStatValue(SocialImpact)` and the social variant **also** multiplies opinion by the same value — i.e. vanilla scales by the **initiator's** impact, mood and opinion sharing one multiplier (this mod scales by the **own** impact — a deliberate divergence, see the About copy).
- **Xenotypes carry zero numeric hooks in 1.6**: `XenotypeDef` holds only gene lists and spawn/combat metadata, **no** `statOffsets` (the old wiki cell is `XenotypeBase`-era race data); stat offsets live on `GeneDef`, and **no vanilla gene touches `SocialImpact`** (`<SocialImpact>` appears only on hats and ritual endings). Gene-level social levers are all frequency or opinion: `lovinMTBFactor` (Libido_Low 2 / _High 0.5), `socialFightChanceFactor` (DeadCalm 0 / Aggressive 2 / Hyper 3), `missingGeneRomanceChanceFactor` 0.2 (Furskin and other appearance genes), `statOffsets PawnBeauty` (Beauty_* ±1/±2 → Pretty/Ugly situational opinions ±20/±40).
- Alternative scaling hook (deliberately unused): `ThoughtDef.effectMultiplyingStat` + `effectMultiplyingStatCurve` scales mood by a stat purely in XML (`Thought.cs:124-126`, memories included), but it reads the **holder's own** stat and **never touches the memory variant's opinion**; scaling by the initiator's charm still requires assigning `moodPowerFactor` in code like `AddInteractionThought`. Vanilla uses it for things like `PsychicSensitivity`, never `SocialImpact`.
- **1.6 player-HUD available surface** (each item verified against `Krafs.Rimworld.Ref 1.6.4871` metadata + decompiled source; full list and cost assessment in `docs/hud-ui-surfaces-1.6.md`): zero-Harmony = bottom-bar `MainButtonDef`, right-click `FloatMenuOptionProvider` (both in use), the **gizmo strip** after selection (hooks: `public virtual ThingComp.CompGetGizmosExtra()` and `Hediff.GetGizmos()`; 1.6 has **no** `CompGetGizmoExtra` interface type — to attach to pawns, add a comp to the `Human` ThingDef via XML `<comps>`), inspect-panel tabs (`ThingDef.inspectorTabs` is `List<Type>`, an XML `<Operation>` extends a vanilla def), `DesignationCategoryDef.specialDesignatorClasses`, the right-side `Alert` column (`AlertsReadout.allAlertTypesCached` scans subclasses ⇒ not even a Def needed), `GameComponent/MapComponent.MapComponentOnGUI`, **the gameplay tip window `TipSetDef` (`TipSetDefOf.GameplayTips`, pure XML)**, `KeyBindingDef`, `HediffDef/GeneDef.renderNodeProperties` overlays, `ITab_Pawn_Log` + `PlayLogEntry_Interaction`, `RoomStatDef` rows, `PawnColumnDef` columns. Harmony-only (judged never-do) = the bottom-right toggle strip (`PlaySettings.DoMapControls` is literally **Private** in metadata; only `DoPlaySettingsGlobalControls` is public) and colonist-bar cells (`ColonistBar.cachedEntries` + `ColonistBarColonistDrawer`'s hard-coded `Icon_*` field table). **Names that do not exist in 1.6** (stop planning against them): `GameUIRootDef`/`GameUITabDef`/`UIDataFolderDef`, `MainTabDef`/`ITabWindow`/`Dialog_InspectTab`, `ArchitectGridDef`/`ArchitectPatternDef`, `TipDef`/`TipTransmitter`, `PlayLogUtility`, `MainDialogCrossMap`.

### Panel and resolution: how the game manages UI scaling (verified 2026-09-22 by decompiling 1.6.4871 `Assembly-CSharp.dll`)

- **`Verse.UI.ApplyUIScale()`** (called per frame by UIRoot): `UI.screenWidth/screenHeight = Screen.width/height ÷ Prefs.UIScale`, and `GUI.matrix` is multiplied by UIScale — **physical resolution only drives rendering; IMGUI and windows live entirely on the logical canvas**: `Window.windowRect`, `Widgets.*`, `Mouse.IsOver` all live in that space. The only correct adaptation: **derive all geometry from `UI.screenWidth/screenHeight`** (ratios + clamps), never read `Screen.width`, never hard-code absolute pixels. The window base class's own `SetInitialSizeAndPosition()` centers on `UI.screenWidth` — follow it.
- **Resolution/UIScale change hook**: `Verse.Window.Notify_ResolutionChanged()` (the WindowStack calls each window; inside the panel also compare `UI.screen*` per frame as a fallback). The default implementation re-runs `SetInitialSizeAndPosition()`. Our policy: never dragged → re-anchor; dragged → map the old relative position proportionally + clamp back on-screen (with `draggable=true` the base class puts `GUI.DragWindow()` on the whole window; regions a control `Use()`d are not eaten; comparing against "last automatic position" detects a drag).
- **Non-modal trio** (all public fields, zero Harmony): `forcePause=false` (no pausing), `absorbInputAroundWindow=false` (input outside the panel is not swallowed, the map stays operable), `layer=WindowLayer.GameUI` (does not occupy the Dialog layer, so other mods' "exit when a dialog exists" heuristics never hit us). `closeOnCancel=false` leaves Esc to the Targeter's pick cancel; `doCloseX=true` uses the base-class ×.
- Draw hooks and assets (all verified): content override is **`public override void DoWindowContents(Rect inRect)`** (not OnGUI; the base already BeginGroups to the content rect, draws optionalTitle and the × itself, inRect is **content-local coordinates** — draw directly, never BeginGroup again); the close hook is **`PostClose()`** (`OnClose` does not exist — CS0115 will teach you); portraits via **`PortraitsCache.Get(pawn, size, Rot4.South)`** — South faces the camera (face), North is the back of the head; all six explicit-rotation vanilla call sites use South (live screenshot 2026-10-04 caught this file's old `Rot4.North` nail as wrong; 1.6 has no no-rotation overload and no `Pawn_PortraitCache`/gutter old names); hover highlight **`Widgets.DrawHighlight(IfMouseover)`** (`DrawLightening` does not exist); `ContentFinder<Texture2D>.Get(path, reportFailure)` — the second parameter is named `reportFailure`; font get/set goes through the **`Text.Font` property** (the `Text.font` field is not visible).
- **Director panel (new in 0.1.0)**: `Dialog_KissDirector` — left avatar frame / heart / right avatar frame + one status line under each frame + a quick-chain button at the bottom; overall size from `UI.screenHeight/1080` (k clamped 0.55~1.35), width additionally clamped to 62% of the logical canvas. **Five user rulings**: right-slot placeholder = `（先选发起方）`; a successful dispatch **keeps the slots** (the pair cooldown turns re-clicking into a message with the real reason); left-click a filled frame = re-pick, right-click = clear (clearing the left also clears the right — the referent changed); quick chain = the existing two-hop flow, dispatch on completion **and echo into the avatar slots**; default position = centered above the bottom bar (`y = UI.screenHeight - height - MainButtonDef.ButtonHeight - 6k`) + draggable. `KissDirector` was demoted to the **picking primitive layer**: `BeginPick` (single hop, avatar frames) / `QuickChain` (two-hop chain, quick dispatch) / `Dispatch` (public; heart and chain share the dispatch+message path); the bottom-bar `Activate()` only calls `OpenOrClose()`; turning the director off in settings makes `KissTicker` close the panel too (`Current?.Close()`); `Current` is set in the ctor, cleared in `PostClose`, and reset per game by the `KissTicker` constructor. Dev log tokens: `pick start/ok/end (generation N)` (old `director on/off`, `pick 1/2` retired).
- One more thing a non-modal panel must switch off: **`Window.preventCameraMotion` defaults to true** — `CameraDriver.AnythingPreventsCameraMotion` scans that field across every window in the stack; one true kills arrow panning, edge pan, and wheel zoom wholesale (`Dialog_KissDirector`'s first live version tripped exactly this; now explicitly false). Also the startup scan `StaticConstructorOnStartupUtility.ReportProbablyMissingAttributes` only looks at "type has static Texture/Material fields and no `[StaticConstructorOnStartup]`" — it does **not** recognize lazy loading; just attach the attribute.
- **Text does not scale with the ratio factor**: fonts (Tiny=16, Small=26 logical pixels) and our `k = screenHeight/1080` are two scales — anywhere "frame width multiplied by k, fixed-size text inside" will wrap/overflow at small k. Text-bearing frames (panel captions) need a **k-free hard minimum width** (`CaptionWidth = max(slot+gap, 122f)`) and row height reserved for "two Tiny lines = 46 logical pixels". Vanilla `Dialog_Options` itself is **fixed 650×600 logical pixels and `SetInitialSizeAndPosition` does not clamp to screen** (decompilation confirmed); on small logical canvases it overflows top/bottom — unsolvable mod-side without Harmony.
- **Text height is measured, never guessed (live-proven twice 2026-10-05)**: hardcoding a band height for a text row clips it — first the watermark, then the CJK subtitle, both despite "generous" constants. Two reasons the guess always loses: CJK glyphs fill the em box and `g/p/y` add descenders on top of line-gap, and these are **font-metric facts orthogonal to canvas size/UIScale** — no layout engine (FerriteLib included) fixes this axis, because even an engine must first *know* the text's real height to reserve room. Correct primitive is vanilla's own `Verse.Text.CalcHeight(text, width)` / `CalcSize`: let the font report its box, add breathing room, derive the band. This is the "responsive" part that actually applies — content sizes the container, not a constant. FerriteLib was considered and rejected for this mod on principle: its value is structural containers (stacks/auto-scroll) for many screens, not measurement, and pulling it in for a one-call fix violates the no-new-runtime-dependency boundary while adding a version-coupling this two-surface mod doesn't need. Rule for all future UI: **measure text, scale canvas via `UI.screen*` — two axes, each fixed on its own, neither substitutes for the other.**
- Second live-panel corrections (2026-09-22, screenshot-proven): (1) the height formula must include the **title row** — `Window.OnGUI` yields another `Margin + 25f` from the content rect when `optionalTitle` is non-empty; missing it pushes the bottom button up into the caption; (2) `Text.WordWrap`'s vanilla contract is **must be true at frame end** (`Verse.Text`'s end-of-frame sentinel `ErrorOnce("Word wrap was false at end of frame")`) — "set false after drawing" in DrawCaption was wrong, default is true, don't touch it; (3) the heart fills **half at a time** (user design): grey base heart, and choosing one side paints that half back to color (this Unity build has no `GUI.DrawTexture` overload with sourceRect — implemented by clipping left/right halves with `GUI.BeginClip`); both sides = full red, dispatchable.
- Every settings slider carries a **right-side numeric field** (2026-09-22 maintainer demanded exact input): row layout "label line + slider + 74px fixed field"; click to edit, Enter/focus-loss commits, quantized by step and clamped, parse failure voids the edit and re-echoes; tick items edit **in ticks** (storage unit = input unit); `pairScope` deliberately has no field (a tier is not a quantity). IMGUI focus test uses `GUI.GetNameOfFocusedControl()` (`GUIUtility.keyboardControl` is an int ID and cannot be compared to names).

## Who can kiss: the three-layer boundary (verified against RimSage 1.6 source, 2026-09-02)

Attaching a job is species-independent; mood and species are **not** isomorphic; "can be ordered" is the initiator's real ceiling.

| Layer | Criterion (vanilla source) | Conclusion |
|---|---|---|
| Technical: can hold a job | `PawnComponentsUtility.CreateInitialComponents` builds `jobs`/`needs`/`stances` for **every** pawn; only `RemoveComponentsOnKilled` clears them | any alive, spawned pawn runs a custom `JobDriver`, regardless of `intelligence` |
| Initiate: can be ordered | `FloatMenuContext` ctor runs `RemoveAll(!CanTakeOrder)`; `CanTakeOrder = IsColonistPlayerControlled ∨ IsColonyMech ∨ IsColonySubhumanPlayerControlled`, and `IsColonist` requires `RaceProps.Humanlike ∧ ¬IsSubhuman` | **animals can never initiate** (`IsColonyAnimal` is not in the set); colony mechs and the player's draftable subhumans can |
| Initiate: menu preconditions | 1.6's `FloatMenuMakerMap.ShouldGenerateFloatMenuForPawn` | downed → `IsIncapped`, cryptosleep, Lord-controlled → no provider generates at all |
| Reward: has mood | `NeedDef Mood`: `minIntelligence=Humanlike` + `developmentalStageFilter=Baby,Child,Adult`, no faction/slave gate | humanlike ⇒ mood: colonists, slaves, prisoners, visitors, traders, raiders, ancients, Creepjoiner |
| Reward: no mood | `RaceProperties.intelligence` has **no initializer** → defaults to `Animal`; every explicit declaration else is `ToolUser` (mechanoids, Odyssey drones, Anomaly fleshbeasts/void entities) | animals/insects/mechs/drones/anomaly creatures have no mood — kissing is action without reward |

- **Trap**: `BaseMutantEntity` (shared by Shambler / Ghoul / AwokenCorpse) carries `disableNeeds=true`. Their race is literally `Human`, `RaceProps.Humanlike` is true, yet `needs.mood == null`. ⇒ the mood test must read the runtime need instance; reading the race would wrongly admit them. (Vanilla's only Humanlike race is `Human`, plus Anomaly's `CreepJoiner` inheriting it.)
- Vanilla has **no** hediff / gene / trait / precept that puts `Mood` into `disablesNeeds` (the disabled ones are Rest/Comfort/Outdoors/Beauty/Food); `Mood` has no `nullifyingPrecepts`/`titleRequiredAny`/`hediffRequiredAny` either. So "humanlike always has mood" holds without exception beyond mutants.
- Social semantics align with `SocialInteractionUtility`: `interactions != null` (only `RaceProps.IsFlesh` builds it), `CapableOf(Talking)`, `Awake()`, not burning, not `MutantDef.incapableOfSocialInteractions`, not `IsInteractionBlocked` (which honors `HediffDef.blocksSocialInteraction` — only Biotech/Odyssey ritual hediffs set it in vanilla).
- `Awake()` = `health.capacities.CanBeAwake` ∧ current `curDriver.asleep == false` (`RestUtility`). ⇒ coma/anesthesia/sleep/cryptosleep blocked; **downed-but-awake still passes**, which is why "kissing a downed pawn" survives as a feature.
- `LifeStageDef.canInitiateSocialInteraction` defaults `true`; vanilla sets it false only on `HumanBaby` (which is also `alwaysDowned=true` — two gates overlap).
- Capacities come from body-part **tags**: `TalkingSource` (human jaw, animal jaw/beak) + `TalkingPathway` (neck). Mechanoids have `TalkingPathway` via `MechanicalNeck` but **no `TalkingSource`** ⇒ `CapableOf(Talking)` is permanently false for them — "must have a mouth to initiate" can only be tested on `RaceProps.IsFlesh`, otherwise `MechanoidCanDo` becomes dead code. The mech `ArtificialBrain` carries `ConsciousnessSource`, so `Awake()` is normally true.
- `MutantDef.whitelistedFloatMenuProviders` is an **empty list** (not null) on all three mutants, so vanilla `SelectedPawnValid` locks them out of the right-click menu entirely; this mod deliberately skips base. Since 2026-10-05 (maintainer ruling "entities = mech-equal treatment") the participation layer no longer blocks `incapableOfSocialInteractions` either — admission is the gate slider's job (mutants are Humanlike, so tiers 3/4 admit them) and moodless settlement speaks through the dedicated `KissPawnMutant` fate table.

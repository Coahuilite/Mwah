# 移动失能与亲吻结束点：实现与验收

当前仍是 `0.3.x` 的待发布 0.3.0；规格先于实现提交为 `719511f`。现行规则见 [KISS-01／05／09](../../openspec/specs/kissing/spec.md) 及 [ADD-02](../../openspec/specs/addons/spec.md)，[采用记录](../../openspec/changes/mobility-and-kiss-completion/adoption.md)保存完整 delta 和历史。

## 实机反馈与当前定位

2026-10-29，维护者确认前包 `803c6ea` 的“表演结束即结束亲吻”生效；但倒地接收方在 1.6 的右键、导演台和快速发配仍失败，移动方随后闲逛。获准只读的 Player.log 启动身份为 **1.6.4871 rev591**，使用该提交的 dev 包。

去身份化的事件顺序为：接收方工作入场并进入原地表演等待 → 移动方工作入场 → 移动方因 `MatchingPartner == null` 中止接近。正常可移动配对及物体吻在同一会话中也有完成结算记录。这个结果否定“上一包已经解决倒地派发”的交付判断；它没有证明是其他模组、原版接管或配对 ID 中哪一个原因。

当前日志缺少接收方工作退出原因及实际接替工作。维护者将用原版 `Toggle job logging` 对双方开启工作日志并重试，实施者随后直接读取同一个日志继续定位。保持现行清醒接收资格，不通过放宽规格接受失败，不把 1.7 快照当作这个 1.6 会话的原生实现证据。

## 前包已实施的改动

- **不能移动的一方原地等待。** 双人台位找不到时，移动方走原版 Touch 备用路线；不能移动的接收方明确使用自己的当前格，不再在入场同步执行中尝试走近远处的发起方。预筛按 Pawn 的实际占格进行可达性评估，支持多格对象的 Touch 语义。
- **手动导演台支持移动回退。** 第一位不能移动时，另一位通过全部发起资格才走过去；提示按实际角色报告。自主撮合仍不交换，双方都不能发起、昏迷／麻醉等原限制仍拒绝。右键继续遵守原版下令入口：不能从倒地选中方下令时，选可动方右键失能者，或用导演台。
- **表演完成即不再“正在亲吻”。** `IsKissing`、共享占用和工作报告按已有完成标记／toil 阶段派生；返程显示“返回原位”。配对及墙／树一致，不再因为对方仍返程而报忙。
- **释放真实预订，而非只改文案。** 配对完成时立即按双方各自 job 释放普通目标／台位预订，不等被动方下一 tick；表演收尾及返程入口同样定向释放。旧返程读档在首个模拟 tick 清理原亲吻预订。步行目的地预订不在此次释放范围，新的工作预订不被旧 job 清除。
- **返程与原目标解耦。** 原搭档或墙／树目标在表演完成后离场，不再使返程失败。返程可被通过资格的新命令接替；旧清理不重启返程，不重复结算。接近／表演期间仍保持匹配及排他。

返程可以继续使用原工作保持连续行走，这不再意味着仍在亲吻。保留既有 Def、类型、字段、toil 序号及 finalizer 安全门；冷却仍在成功入场后登记，关闭冷却豁免时返程中也可能因真实冷却被拒绝，而不是“已经在亲了”。

## 证据及边界

源码定位表明旧失能备用走位会在被动工作先入场时因不能移动而失败；旧占用仅按 driver 类型、静态报告仍写亲吻，且普通预订一直保留到整个工作清理。这些是源代码层的失败链路，不是代理执行的游戏复现。

本地 RimSage 完整 `1.7.4990 rev1069` 快照验证通过，相关程序集无反编译警告。核对了 StartJob 同步 ReadyForNextToil、Awake、GetReport 和 ReservationManager.ReleaseClaimedBy(Pawn, Job)。释放按具体工作身份进行，不使用清除 Pawn 全部预订的接口。

既有 `verify-local.ps1` 双版本 × Dev／Steam／GitHub 构建零警告／零错误，219 对双语键、25 个 XML、7／112 个 DefOf／Def、102 行天意表、两份 DLL 的 41 个符号、18 个设置字段及零 Harmony 门通过。`pack-dev.ps1 -Zip` 负责生成完整双版本包，实际包另经隐私扫描；交付使用提交后生成、无 dirty 标记的包，身份以 `version.txt` 和 DLL 产品版本为准。没有新增单元测试或等价换名脚本，没有运行或安装游戏。

维护者此前已确认社交压缩起效，该观察仍有效，记录在[压缩实施记录](social-impact-soft-cap.md#维护者已确认的观察)；不将其扩写为本次状态修复已实机通过。

## 这次优先怎么实机验收

使用完整新包，先保存独立测试存档，保留原存档与设置。用清醒但不能移动的 A、可移动的 B；不要用昏迷来代替移动失能。

1. **失能派发**：导演台先 A 后 B、再先 B 后 A；各看近距离和远距离情况。A 应留原位，B 到其身边后才开始表演和奖励。右键则选 B 点 A。两者都不能移动应拒绝，不应显示已开始。
2. **结束点与再次亲吻**：开启“亲完回原位”和冷却豁免，让可移动双方从较远位置开始。爱心表演结束、奖励出现后，返程报告应变为“返回原位”。尚未回到原位时，给其中一位新的配对／亲墙／亲树请求，应能替换返程且不再报“已经在亲了”。关闭豁免再试，仍应检查正常冷却。
3. **目标释放与工作所有权**：亲墙／亲树结束但仍返程时，让另一位去亲同一目标；目标不应继续被旧吻预订。给返程 Pawn 新的普通移动命令或让其受击，旧回程不能抢回；原搭档返程、换工作或离场不重复发奖。
4. **存读档**：接近／表演中的原吻仍按匹配继续；返程存档读取后仍显示返程、不重复结算，首个模拟 tick 后旧目标不再被该返程预订。

以上仍待实际游戏结果。反馈给出包内提交身份、游戏 build、入口及哪一阶段失败即可；不要将私人日志或本地路径提交到仓库。该切片的验收由[任务 5](../../openspec/changes/mobility-and-kiss-completion/tasks.md)管理，原变更的其他实机缺口保持各自责任。

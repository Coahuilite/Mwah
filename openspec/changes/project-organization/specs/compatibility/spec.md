# 跨版本维护约束增量

状态：2026-11-09 按本轮项目整理／建立规格授权写入现行合同；无运行架构迁移。本文保存采用差量，不是另一套现行正文。

## ADDED Requirements

### Requirement: NATIVE-04 共享规则维护源与窄原生适配
对 RimWorld 1.6／1.7，模组 SHALL 单源维护共同玩法规则、状态含义、Def 和本地化；构建生成的版本副本 SHALL NOT 成为独立编辑源。原生差异 SHALL 限于实际不同的框架、引用、API 或加载合同，不复制无差异的执行及结算规则；适配 SHALL 保留旧入口、数据含义和原有使用条件。该保证 SHALL NOT 要求跨版本共用同一个 DLL 或引入额外核心程序集。

#### Scenario: 修改共同结算规则
- **WHEN** 维护者批准改变适用于两个 minor 的同一结算规则
- **THEN** 修改其共同维护源，两个目标构建消费同一规则，不要求人工在两份业务实现间同步。

#### Scenario: 一个目标的原生调用发生变化
- **WHEN** 只有一个受支持 minor 的原生 API 或框架合同变化
- **THEN** 适配该接缝，共享的请求和结算含义不分叉，未采用新能力的旧调用者不承担新前提。

#### Scenario: 构建和编辑内容
- **WHEN** 从共同内容源生成两个版本的分发目录
- **THEN** 分发副本仍是派生内容，后续规则和语言修改回到维护源，不因副本存在而形成两个合同。

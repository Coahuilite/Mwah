# 0.4.x 共享内容与执行生命周期整理

状态：**2026-11-09 已核对采用，goal 执行中**，见 [adoption](adoption.md)。维护者已将范围从 VNPE 条件目录扩大为全模组共享源码／内容源、双原生构建及局部生命周期整理，并授权本地／远端 `0.4.x` 与开发完成、隐私审查后的推送。当前执行和真实证据由 [tasks](tasks.md)管理。

## Why

当前 C# 已经单源，但共同 Def／语言仍以 `1.6/` 为编辑源，并在安装包复制成两套。此次应把共同内容明确归到共享根，让源码、内容、原生差异和可选兼容各有清晰边界；同时检查执行和界面中依赖布尔量、原生阶段索引、回调顺序的隐式状态，避免目录整理后仍留下难以维护的责任关系。

## 已采用目标

1. `Source/Mwah/` 保留一个项目／命名空间／程序集身份，继续编译 1.6 `net472` 和 1.7 `net10.0`。只适配真实框架／游戏 API 差异，不拆核心 DLL，不包裹所有 Verse 对象。
2. **采用 `Common/` 作为唯一共同内容源，同时作为两版安装包实际共用的内容根**；不再把相同 Def／语言复制进两个 minor。两个 minor 只放各自原生 DLL 及将来有实证需要的版本差异。
3. VNPE 目标登记和专用文案使用单独 `Compatibility/VanillaNutrientPasteExpanded/` 根，由两版的 LoadFolders 条件选择；共同 Paste 奖励仍在 Common，通用登记消费仍在主程序集。
4. 对隐式状态按所有者、寿命和副作用评估：优先整理 Job 完成／收尾／返程、配对绑定与导演台点选会话；设置、冷却、自主撮合和诊断按证据决定保留或局部收口，不为统一形式全面重写。

目录与依赖见 [design](design.md)，源码状态清单及改动判断见 [state-machines](state-machines.md)，执行顺序与责任见 [tasks](tasks.md)。

## 现行边界必须显式迁移

采用前 AGENTS／NATIVE-02 将运行内容限定在版本目录，与 Common／Compatibility 运行根冲突。已先采用[完整修订](specs/compatibility/spec.md)，同步 AGENTS 为“显式加载根＋按 minor 互斥原生程序集”，再开始迁移。其余共同玩法、身份、设置、天意、PowerOn、站位、单槽和已通过的识智奖励不变。

## 范围与交付

- 共享内容搬迁、LoadFolders、暂存／验证／直接读者，以及 VNPE 登记消费形成一个完整交付切片。
- 生命周期整理形成另一个切片；先记录真实转移与不变量，再做有收益的局部显式化。原生 Toil 仍拥有执行进度，不能另建一套并行 FSM 或全局会话管理器接管 Pawn。
- 更新模组 `0.4.0` 的未发布版本轴及对应说明，不把开发分支推送当作正式发布。既有 0.3.0 发布记录保持原义。
- 提供完整双版本开发包、有效离线证据、受影响原生路径的维护者结果／明确缺口，以及最后的隐私审查和远端 `0.4.x` 推送／CI 结果。

## 分支与授权解释

本地／远端 `0.4.x` 按 **Git 开发分支**处理，不复制第二套项目工作目录。进入开发后从当前已提交基线 `bedea41` 分出；先核对是否有同名分支，不能覆盖它。保留原 `0.3.x`，不 reset、amend、rebase 或强推。

维护者的后续推送授权已给出：达到约定开发交付条件并完成隐私审查后，推送 `origin/0.4.x`，观察对应提交的 CI；不再为这一步重复索取权限。它不包含更改远端 URL／默认分支、合入 main、tag、GitHub Release 或工坊发布。原“先对齐、不开发”的检查点已由维护者明确结束，当前按 goal 执行。

## 验收重点

共享内容实际只保留一份；每个游戏组合只加载对应 Mwah.dll；未启用 VNPE 时不加载兼容登记。旧配置、Job／Thought／旁白身份与执行中存档含义保留；取消不发完成奖励、结算不重复、返程不继续占用。维护者已有亲吻点／识智观察按原范围复用，仅对加载或生命周期改变的前提补证。

## 不做

不支持新的游戏 minor，不增加玩家玩法，不增 Harmony／第三方 DLL 强制依赖，不运行游戏、不建安装链接、不修改第三方模组，不新增单元测试或等价换名脚本，不清理或提交无关 `art/`。

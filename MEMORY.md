After the 2026-09-02 boundary consolidation, this mod's own preconditions are written as `KissBoundary`'s layers, never approximating "capability" with "species". The reward side stays conservative (see engineering decisions). The workspace folder name `every_pawn_kiss_each_other/` is a historical value and carries no identity.
- Explicitly never (not a to-do): world map / caravan tiles, RimWorld Multiplayer sync, true body-contact kiss animation, downed pawns as initiators (would need Harmony to open vanilla gates).

## Vanilla capability boundaries (verified against RimSage 1.6 + Odyssey source, 2026-09-02)

Read before changing implementation: these are the grounds this mod's shape stands on.

- **Right-click entry self-registers**: `FloatMenuMakerMap.Init()` reflectively instantiates `typeof(FloatMenuOptionProvider).AllSubclassesNonAbstract()` → a mod provider enters the menu chain with no Def/XML/patch. Base-class gates: `Drafted/Undrafted/Multiselect/RequiresManipulation/MechanoidCanDo/CanSelfTarget/CanTargetDespawned/IgnoreFogged` + `SelectedPawnValid/TargetThingValid/TargetPawnValid/Applies/GetOptionsFor(Thing|Pawn)`.
- **The `SelectedPawnValid` trap**: this mod's override **deliberately skips base** (base would cut everything by the mutant whitelist; mechanism in the last bullet of "Who can kiss"); `MechanoidCanDo => true` is therefore a declared intent, not a capability.
- **Vanilla hard gates (unbypassable at provider level)**: `GetOptions`' first line requires the click inside `Find.CurrentMap`; the `ShouldGenerateFloatMenuForPawn` exclusion list (see the "Who can kiss" table) ⇒ **downed pawns cannot initiate**, but can be targets.
- **Grounds for rejecting the `ability` route**: `PawnComponentsUtility.AddComponentsForSpawn` creates `pawn.abilities` only for `Humanlike || IsMechanoid`; Odyssey's `FleshType.Drone` (`isOrganic=false`) has no `interactions` tracker either. Neither Ability nor `InteractionDef` covers "every pawn" — only a FloatMenu provider does.
- **Approach/facing primitives**: `pather.StartPath(target, PathEndMode.Touch)`, `SocialInteractionUtility.BestInteractableCell/IsGoodPositionForInteraction(≤6 cells + LineOfSight)`, `rotationTracker.FaceTarget(...)`, `GenAdj.AdjacentTo8WayOrInside(Thing,Thing)` (correct for multi-cell bodies). 1.6 **removed `Pawn.CanMove`**; the mobility read is `health.capacities.CapableOf(PawnCapacityDefOf.Moving)` plus the `RaceProps.doesntMove` special case.
- **Map picking uses vanilla `Find.Targeter`; never hand-roll MouseDown in GameComponentOnGUI**: `Targeter.BeginTargeting(...)` brings pointer-following highlight (`GenDraw.DrawTargetHighlight`), mouse attachment (`GenUI.DrawMouseAttachment` + `Widgets.MouseAttachedLabel`), left-click commit, right-click/Esc cancel, and is processed after windows in the map input pipeline — persistent windows (Dev palette) cannot kill the mode the way hand-rolled OnGUI gets killed. `caster: null` ⇒ `ConfirmStillValid`'s "initiator must be selected" check is skipped entirely ⇒ picking works with nothing selected. Two-hop picking chains via consecutive `BeginTargeting` (it resets `needsStopTargetingCall` to false, so starting hop two inside hop one's action survives the following `StopTargeting` — same trick as vanilla `DestinationSelector`). `TargetingParameters.ForPawns()` also selects enemies.
- **A GameComponent must never auto-exit input mode because "some window kind exists"**: `WindowStack.NonImmediateDialogWindowOpen` is true whenever any non-Immediate Dialog-layer window sits in the stack — many mods keep one open permanently, so the director got `End()`-ed on the next event after every `Begin`: "clicking does nothing, not even the prompt bar", while the log showed `director on` repeatedly and `director off` never. Correct: yield by `return` only (never exit the mode), and gate clicks precisely with `WindowStack.GetWindowAt(mousePos)`.
- **Two hard localization facts (settled by the 2026-09-04 translation report)**: the Chinese folder must be named `ChineseSimplified` (matching packages that do display correctly; `SimplifiedChinese` as used by `let_me_gnaw_on_you` is wrong). Inside `DefInjected/<Type>/<file>.xml`, `<LanguageData>`'s children must be **flat dotted keys `DefName.fieldPath`**, not nested def format — `DefInjectionPackage.SetDefFieldAtPath` takes `path.Split('.')[0]` as the defName, so `<MWAH_KissDirector><label>…</label></MWAH_KissDirector>` turns the top name into a bare defName with no field path and silently lands in the report's "missing" section (all four injected files tripped this; the Keyed check cannot see it). List fields use indexes: `MWAH_Kissed.stages.0.label` (313 real mod files do this; the report's printed `stages.kissed_by` is a human suggestion, not writable). `verify-local` now gates it: top names must contain `.` with a real defName prefix. Diagnostic: options menu "save translation report" → desktop `TranslationReport.txt`; "missing" = wrong key format or file unread, "load errors" = type/defName resolution failure.
- **A persistent window must never close input mode or skip drawing**: Dev palette is a non-Immediate Dialog-layer window; "return/End when any dialog exists" leaves the director without its prompt bar during debugging. Correct: draw the prompt unconditionally, yield only for the click landing point (`WindowStack.GetWindowAt(mousePos)`).
- **Facing authority**: `toil.handlingFacing = true` ⇒ `Pawn_RotationTracker.UpdateRotation` early-exits at its very top (skipping even the `job.rotateToFace` and `Drafted` branches); afterwards `rotationTracker.Face/FaceCell/FaceTarget` is the only writer. Vanilla standing chat (`JobDriver_StandAndBeSociallyActive`, `JobDriver_GotoAndStandSociallyActive`) is exactly "handlingFacing + Face every tick + pather.StopDead() every tick" — copy it; `Job` additionally has `lookDirection`/`forceMaintainFacing` for "face one direction only".
- **`GameComponent` requires a `(Game)` constructor**: `Game.FillComponents` calls `Activator.CreateInstance(item2, this)` (this = `Game`). Without it: no compile error, no dialog — one `Could not instantiate a GameComponent of type X: MissingMethodException` line in Player.log and the component silently never runs. The number-one cause of "code written yet totally inert"; check the instantiation contract before adding any component class.
- **Heart fleck**: exactly `FleckMaker.ThrowMetaIcon(cell, map, FleckDefOf.Heart)` (vanilla Lovin uses a 100-tick constant). `Heart` is a **FleckDef** (`Things/Mote/Heart`, `MetaOverlays`); there is no `Mote_Heart`.
- **Two-person lock**: the `JobDriver_Lovin` mirror-job technique (give the partner `StartJob(same def, self, InterruptForced)`); `TryTakeOrderedJob(job, JobTag.Misc)` for courtesy requests like walking home; `Pawn_JobTracker` auto-chains `Wait_MaintainPosture` after a successful job.
- **Mood scaling**: `Thought_Memory.MoodOffset() = stage.baseMoodEffect × moodPowerFactor + moodOffset`; `durationTicksOverride` changes duration per instance; `ThoughtDef.DurationTicks = durationDays × 60000` (1 day = 24 game hours; this mod's durationDays and the "mood duration" factory default are both 1 day and must stay aligned). Vanilla `Pawn_InteractionsTracker.AddInteractionThought` is public static but multiplies by the **other** pawn's `SocialImpact` (and pushes the same value into opinion), gated on `Talking` capacity and the `interactions` tracker → this mod writes its own, using the **own** `SocialImpact`, mood and opinion sharing one multiplier.
- **Non-exploding edge**: `SkillNeed_BaseBonus.ValueFor` returns `1f` when `pawn.skills == null`, and `SocialImpact` is `neverDisabled` → reading the stat on skill-less units is safe.
- **Social-semantics side-effect switch**: `Thought_MemorySocial.Init()` runs inside `ThoughtMaker.MakeThought` and writes `opinionOffset = stage.baseOpinionOffset` → the multiplier must be applied after MakeThought to count; `ShouldDiscard` requires `otherPawn != null && opinionOffset != 0`.
- **Bottom bar extends; the bottom-right toggle strip does not**: `MainButtonDef` is a plain Def (`workerClass/tabWindowClass/order/minimized/buttonVisible/defaultHotKey`) — pure XML adds a bottom-bar button; `MainButtonsRoot.DoButtons()` consults `Worker.Visible` every frame ⇒ overriding `Visible` gives settings-driven show/hide, zero Harmony. But the bottom-right display toggles are **not data-driven**: `PlaySettings.DoMapControls(WidgetRow)` is a wall of hard-coded `row.ToggleableIcon(...)` calls, no Def, no list ⇒ adding one cell would need Harmony (red line, never). Bar order is each Def's `order` (vanilla Architect=1…Factions=90, Mechs=45, Ideos=100, **Menu gear=500**), no grouping; **the last visible button absorbs leftover width**. There is also **no collapse/expand state**: more buttons just narrow (width = screen ÷ visible count, `minimized` takes half); the 1.5 archon ring has zero hits in 1.6 source.
- **Logging infrastructure ceilings**: Player.log has no per-line timestamps, a global 10000-entry Unity cap (afterwards `Debug.unityLogger.logEnabled = false` swallows every `Log.*`), and identical-text folding stops recording at 99 ⇒ every instrument line must carry `t=<tick>` and a unique field. The settings file stores only non-defaults (a diff, not a snapshot); settlement evidence lives in the save XML itself. **Details and trade-offs: `docs/kiss-trace-logging-design-zh.md`.**
- **Unit constants**: `GenTicks.TicksPerRealSecond = 60`, `GenDate.TicksPerDay = 60000` → 1 game hour = 2500 ticks.
- Greyed-item convention: `new FloatMenuOption(label, null, priority…)` (null action = disabled), reason in parentheses inside the label; `FloatMenuUtility.DecoratePrioritizedTask` marks "will preempt"; the ready-made priority is `MenuOptionPriority.InitiateSocial`.

### Panel and resolution: how the game manages UI scaling (verified 2026-09-22 by decompiling 1.6.4871 `Assembly-CSharp.dll`)

- **`Verse.UI.ApplyUIScale()`** (called per frame by UIRoot): `UI.screenWidth/screenHeight = Screen.width/height ÷ Prefs.UIScale`, and `GUI.matrix` is multiplied by UIScale — **physical resolution only drives rendering; IMGUI and windows live entirely on the logical canvas**: `Window.windowRect`, `Widgets.*`, `Mouse.IsOver` all live in that space. The only correct adaptation: **derive all geometry from `UI.screenWidth/screenHeight`** (ratios + clamps), never read `Screen.width`, never hard-code absolute pixels. The window base class's own `SetInitialSizeAndPosition()` centers on `UI.screenWidth` — follow it.
- **Resolution/UIScale change hook**: `Verse.Window.Notify_ResolutionChanged()` (the WindowStack calls each window; inside the panel also compare `UI.screen*` per frame as a fallback). The default implementation re-runs `SetInitialSizeAndPosition()`. Our policy: never dragged → re-anchor; dragged → map the old relative position proportionally + clamp back on-screen (with `draggable=true` the base class puts `GUI.DragWindow()` on the whole window; regions a control `Use()`d are not eaten; comparing against "last automatic position" detects a drag).
- **Non-modal trio** (all public fields, zero Harmony): `forcePause=false` (no pausing), `absorbInputAroundWindow=false` (input outside the panel is not swallowed, the map stays operable), `layer=WindowLayer.GameUI` (does not occupy the Dialog layer, so other mods' "exit when a dialog exists" heuristics never hit us). `closeOnCancel=false` leaves Esc to the Targeter's pick cancel; `doCloseX=true` uses the base-class ×.
- Draw hooks and assets (all verified): content override is **`public override void DoWindowContents(Rect inRect)`** (not OnGUI; the base already BeginGroups to the content rect, draws optionalTitle and the × itself, inRect is **content-local coordinates** — draw directly, never BeginGroup again); the close hook is **`PostClose()`** (`OnClose` does not exist — CS0115 will teach you); portraits via **`PortraitsCache.Get(pawn, size, Rot4.South)`** — South faces the camera (face), North is the back of the head; all six explicit-rotation vanilla call sites use South (live screenshot 2026-10-04 caught this file's old `Rot4.North` nail as wrong; 1.6 has no no-rotation overload and no `Pawn_PortraitCache`/gutter old names); hover highlight **`Widgets.DrawHighlight(IfMouseover)`** (`DrawLightening` does not exist); `ContentFinder<Texture2D>.Get(path, reportFailure)` — the second parameter is named `reportFailure`; font get/set goes through the **`Text.Font` property** (the `Text.font` field is not visible).
- **Director panel (new in 0.1.0)**: `Dialog_KissDirector` — left avatar frame / heart / right avatar frame + one status line under each frame + a quick-chain button at the bottom; overall size from `UI.screenHeight/1080` (k clamped 0.55~1.35), width additionally clamped to 62% of the logical canvas. **Five user rulings**: right-slot placeholder = `（先选发起方）`; a successful dispatch **keeps the slots** (the pair cooldown turns re-clicking into a message with the real reason); left-click a filled frame = re-pick, right-click = clear (clearing the left also clears the right — the referent changed); quick chain = the existing two-hop flow, dispatch on completion **and echo into the avatar slots**; default position = centered above the bottom bar (`y = UI.screenHeight - height - MainButtonDef.ButtonHeight - 6k`) + draggable. `KissDirector` was demoted to the **picking primitive layer**: `BeginPick` (single hop, avatar frames) / `QuickChain` (two-hop chain, quick dispatch) / `Dispatch` (public; heart and chain share the dispatch+message path); the bottom-bar `Activate()` only calls `OpenOrClose()`; turning the director off in settings makes `KissTicker` close the panel too (`Current?.Close()`); `Current` is set in the ctor, cleared in `PostClose`, and reset per game by the `KissTicker` constructor. Dev log tokens: `pick start/ok/end (generation N)` (old `director on/off`, `pick 1/2` retired).
- One more thing a non-modal panel must switch off: **`Window.preventCameraMotion` defaults to true** — `CameraDriver.AnythingPreventsCameraMotion` scans that field across every window in the stack; one true kills arrow panning, edge pan, and wheel zoom wholesale (`Dialog_KissDirector`'s first live version tripped exactly this; now explicitly false). Also the startup scan `StaticConstructorOnStartupUtility.ReportProbablyMissingAttributes` only looks at "type has static Texture/Material fields and no `[StaticConstructorOnStartup]`" — it does **not** recognize lazy loading; just attach the attribute.
- **Text does not scale with the ratio factor**: fonts (Tiny=16, Small=26 logical pixels) and our `k = screenHeight/1080` are two scales — anywhere "frame width multiplied by k, fixed-size text inside" will wrap/overflow at small k. Text-bearing frames (panel captions) need a **k-free hard minimum width** (`CaptionWidth = max(slot+gap, 122f)`) and row height reserved for "two Tiny lines = 46 logical pixels". Vanilla `Dialog_Options` itself is **fixed 650×600 logical pixels and `SetInitialSizeAndPosition` does not clamp to screen** (decompilation confirmed); on small logical canvases it overflows top/bottom — unsolvable mod-side without Harmony.
- Second live-panel corrections (2026-09-22, screenshot-proven): (1) the height formula must include the **title row** — `Window.OnGUI` yields another `Margin + 25f` from the content rect when `optionalTitle` is non-empty; missing it pushes the bottom button up into the caption; (2) `Text.WordWrap`'s vanilla contract is **must be true at frame end** (`Verse.Text`'s end-of-frame sentinel `ErrorOnce("Word wrap was false at end of frame")`) — "set false after drawing" in DrawCaption was wrong, default is true, don't touch it; (3) the heart fills **half at a time** (user design): grey base heart, and choosing one side paints that half back to color (this Unity build has no `GUI.DrawTexture` overload with sourceRect — implemented by clipping left/right halves with `GUI.BeginClip`); both sides = full red, dispatchable.
- Every settings slider carries a **right-side numeric field** (2026-09-22 maintainer demanded exact input): row layout "label line + slider + 74px fixed field"; click to edit, Enter/focus-loss commits, quantized by step and clamped, parse failure voids the edit and re-echoes; tick items edit **in ticks** (storage unit = input unit); `pairScope` deliberately has no field (a tier is not a quantity). IMGUI focus test uses `GUI.GetNameOfFocusedControl()` (`GUIUtility.keyboardControl` is an int ID and cannot be compared to names).

## Who can kiss: the three-layer boundary (verified against RimSage 1.6 source, 2026-09-02)

Attaching a job is species-independent; mood and species are **not** isomorphic; "can be ordered" is the initiator's real ceiling.

| Layer | Criterion (vanilla source) | Conclusion |
|---|---|---|
| Technical: can hold a job | `PawnComponentsUtility.CreateInitialComponents` builds `jobs`/`needs`/`stances` for **every** pawn; only `RemoveComponentsOnKilled` clears them | any alive, spawned pawn runs a custom `JobDriver`, regardless of `intelligence` |

- **Trap**: `BaseMutantEntity` (shared by Shambler / Ghoul / AwokenCorpse) carries `disableNeeds=true`. Their race is literally `Human`, `RaceProps.Humanlike` is true, yet `needs.mood == null`. ⇒ the mood test must read the runtime need instance; reading the race would wrongly admit them. (Vanilla's only Humanlike race is `Human`, plus Anomaly's `CreepJoiner` inheriting it.)
- Vanilla has **no** hediff / gene / trait / precept that puts `Mood` into `disablesNeeds` (the disabled ones are Rest/Comfort/Outdoors/Beauty/Food); `Mood` has no `nullifyingPrecepts`/`titleRequiredAny`/`hediffRequiredAny` either. So "humanlike always has mood" holds without exception beyond mutants.
- Social semantics align with `SocialInteractionUtility`: `interactions != null` (only `RaceProps.IsFlesh` builds it), `CapableOf(Talking)`, `Awake()`, not burning, not `MutantDef.incapableOfSocialInteractions`, not `IsInteractionBlocked` (which honors `HediffDef.blocksSocialInteraction` — only Biotech/Odyssey ritual hediffs set it in vanilla).
- `Awake()` = `health.capacities.CanBeAwake` ∧ current `curDriver.asleep == false` (`RestUtility`). ⇒ coma/anesthesia/sleep/cryptosleep blocked; **downed-but-awake still passes**, which is why "kissing a downed pawn" survives as a feature.
- `LifeStageDef.canInitiateSocialInteraction` defaults `true`; vanilla sets it false only on `HumanBaby` (which is also `alwaysDowned=true` — two gates overlap).
- Capacities come from body-part **tags**: `TalkingSource` (human jaw, animal jaw/beak) + `TalkingPathway` (neck). Mechanoids have `TalkingPathway` via `MechanicalNeck` but **no `TalkingSource`** ⇒ `CapableOf(Talking)` is permanently false for them — "must have a mouth to initiate" can only be tested on `RaceProps.IsFlesh`, otherwise `MechanoidCanDo` becomes dead code. The mech `ArtificialBrain` carries `ConsciousnessSource`, so `Awake()` is normally true.
- `MutantDef.whitelistedFloatMenuProviders` is an **empty list** (not null) on all three mutants, so vanilla `SelectedPawnValid` locks them out of the right-click menu entirely; this mod deliberately skips base. Since 2026-10-05 (maintainer ruling "entities = mech-equal treatment") the participation layer no longer blocks `incapableOfSocialInteractions` either — admission is the gate slider's job (mutants are Humanlike, so tiers 3/4 admit them) and moodless settlement speaks through the dedicated `KissPawnMutant` fate table.

- Ambient kissing (2026-09-02 maintainer demand "所有 pawn 都啵嘴") runs as `KissAmbient : GameComponent` timed matchmaking, **only for pawns the player cannot command** (test `KissBoundary.UnderPlayerManagement = IsPlayerControlled ∨ IsColonyAnimal`, i.e. own animals count as player-side); commandable pawns remain right-click only.

  Reason: vanilla `FloatMenuContext` first does `RemoveAll(!CanTakeOrder)` — foreign pawns cannot even be selected; zero Harmony has no workaround.

- **Never start a job synchronously inside a toil's finish action (live-proven 2026-09-04)**: `TryTakeOrderedJob` starts the job **synchronously** when the pawn is idle, and the new job's StartJob ends the old job that is mid-finish ⇒ the old job's finish action re-enters ⇒ infinite recursion within one tick. Scene of the crime: one log line repeated to Unity's fold cap of 99, `Mwah-trace.log` stalling, main thread frozen for seconds, process vanishing without "not responding", dump bottoming out in ntdll. Hence "walk home" became a queue (`KissReturnQueue.Enqueue`), drained next tick by `KissTicker.GameComponentTick`; every finish action carries an idempotency gate. **No finish action may ever call StartJob/TryTakeOrderedJob directly.**
- **Debugger choice (measured 2026-09-03; gating moved to runtime 2026-09-30)**: dnSpy-class debuggers attach via ICorDebug, CLR-only; RimWorld runs MonoBleedingEdge ⇒ **live attach cannot see the managed stack**; dnSpy is worth keeping only for decompilation. Mono soft-debugging needs `--debugger-agent` at launch — unrealistic for an installed Steam copy. Hence the bypass sampler `KissTrace`: a background thread at 1Hz copies the phase stamps written by the main thread (begin/walk/perform/return + remaining ticks; the lock phase disappeared with the truce-window rework) into `Mwah-trace.log` in the savedata folder; main thread hangs ⇒ the file stops; crash ⇒ read the tail. Old regime: the class vanished at compile time in release builds; since 2026-09-30 it is resident in all builds, governed by the settings-page "diagnostic logs" runtime switch (off ⇒ Sample returns immediately, writes nothing).

The maintainer's reason: the player is super-intelligence's hand and may matchmake anyone.

- Kiss clock = **initiator's alone** (live-proven 2026-09-04; exit mechanism updated with the truce-window rework 2026-09-28): when both sides counted their own 150 ticks, whoever was processed first in the same tick hit completed=True and ended the job first, and the other side's symmetric fail check instantly kicked the initiator back to completed=False; Settle requires "initiator ∧ completed=True", so in the half of runs where the passive side finished first nobody got mood (measured: "not 100% of pawns had mood"). The passive side still **never counts down**: the old version ended the whole job via "partner dropped out ⇒ symmetric failure"; now the initiator's finished state is the in-job return leg (still inside the job) where the symmetric failure cannot catch it, so the passive side reads `PartnerDriver.completed` (or driver disappearance) and **follows into the return leg** — the exit changed from "scatter" to "walk home one after another", settlement ownership unchanged.
- **Attribution discipline (repeatedly proven in this project, cross-project)**: when the engine's authoritative output exists (translation reports, crash dumps, `FinalizeInit` self-proof logs), never stop at speculation; **never default-explain with "the user installed an old package"** (this project misjudged that way twice; both times it was our own bug); instrument lines must carry unique fields (`t=`/counters), otherwise Unity's fold-at-99 exactly hides "the same call re-entered N times".
- Kiss positioning = **fixed stage** (2026-09-03; since 2026-09-28 the search moved into `KissStage`, executed synchronously by `KissUtility.Start` before both jobs are created): a pair of left-right adjacent static cells, each walks to their own (own cell stored in the job's `TargetIndex.B`), **each job reserves only its own cell + the partner pawn** (the old form had the initiator reserve both cells; ownership split after the same-frame dual start, coverage unchanged). The immobile side is nailed to its current cell, so the walking one circles to its side — "kissing a downed pawn" therefore also gets left-right facing. The abandoned form ("passive side closes in via `PathEndMode.Touch` + active side recomputes the side cell every tick") produced front/back positioning because Touch ignores direction and the target drifted with the partner's movement; facing could then only be North/South. Bodies 2x2 and larger do not fit the model and fall back to Touch. Role recognition: `TargetIndex.C` is always the initiator, "I am not C" = passive — no more guessing from whether B was filled. **Seat-swap deadlock iron law (live-proven 2026-10-04)**: `Usable` always rejects **the other party's current cell** — after same-frame dual start, "my stage = your position, yours = mine" is a mutual wait-for-you-to-move deadlock (vanilla pathing never finishes on a cell occupied by another pawn); both burn their walk budgets and silently scatter within a second of begin (the trace never even catches a walk phase). The old serial entry (passive side departing only at lock) was structurally immune; same-frame start created it. One's own current cell remains allowed (zero-cost arrival).
- **Truce window = job lifetime** (2026-09-28 triple ruling; 10-04 added the seat-swap law): the "coexist peacefully" window for hostile kiss targets covers **approach + performance + departure** in full, with zero new primitives — job ownership natively suspends the think tree. Three pieces: (1) both jobs start on the same frame (`KissUtility.Start`); (2) the return leg lives inside the job (`KissReturn` shared toil, 1200-tick hard cap, stop-loss ends in place, queue as backstop); (3) the passive side reads the initiator's `completed` flag to follow into the return (see the kiss-clock entry). **Rulings**: no distinction between mechanoid and organic — everyone flips hostile only when the job ends; **the combat gate binds ambient only** (`KissBoundary.InCombatNow`: one of AttackMelee/AttackStatic/SocialFight) — player-issued orders (right-click / director) override everything: "if super-intelligence wants two pawns to kiss, they kiss" (same constitution as noCooldowns). **Damage self-destruct gate**: both drivers override `JobDriver.Notify_DamageTaken` (the job tracker calls it **before** the playerForced and 180-tick-cooldown gates, synchronously on the damage event itself; vanilla precedent: PredatorHunt/TendPatient), criterion `ExternalViolenceFor ∧ canInterruptJobs` ⇒ zero latency, one clock across all three paths (the dead-end of relying on `checkOverrideOnDamage` is archived in OBLIVIONIS). **The warqueen case (closed)**: spawning (`CompMechCarrier`) and firing (its turret) are both think-tree job channels, silenced together by job containment; already-spawned war urchins are independent pawns outside the pair truce. **1.6 API facts (nailed this round)**: `JobDriver` has no overridable `Cleanup` (end-of-job registration goes in a finish action); `Pawn_JobTracker.StartJob` returns **void** (compare `pawn.CurJob`); attack job names are `AttackMelee`/`AttackStatic` (old `Attack`/`Manhunt`/`Berserk` do not exist); XML root-element short names resolve only for whitelisted namespaces (see the addon entry). Old saves incompatible (0.1.0 unreleased, no compat layer).
- **Same-frame dual job start races vanilla's synchronous toil chain (fixed 2026-10-04, core feature was 100% broken)**: `Pawn_JobTracker.StartJob` runs `curDriver.ReadyForNextToil()` **at the call site** (verified by decompiling 1.6.4871, not inferred), so an `Instant` first toil (our `ToilBegin`) chains synchronously into the next toil, and `CheckCurrentToilEndOrFail` evaluates `endConditions` **before** that toil's `initAction` — and in 1.6 `Toil.AddFailCondition` writes into `endConditions`. So when `KissUtility.Start` lands the passive job first, its `ToilGotoStage` entry check reads the initiator's `CurJob` before the initiator's `StartJob` has run ⇒ both mirror jobs abort on the same frame ("partner left the kiss" misread as "partner has no job yet"). The 09-28 truce-window change planted it; live testing only exposed it 10-04. Fix = startup-frame grace: the partner-left check returns false while `TicksGame <= job.startTick` (`StartJob` sets `startTick` to the landing tick), so neither side judges the other absent until both jobs exist; real departures (death / job steal / damage break) all land on later ticks and still fire. **General law: any "is my partner still doing X" entry-time fail condition on a job started in the same frame as its mirror MUST carry a `startTick` grace — order of the two `StartJob` calls cannot fix it (whichever lands first sees the other not-yet-started).**

- **Chained-Targeting cleanup race (fixed 2026-09-10)**: vanilla event order is action → StopTargeting → actionWhenFinished, so hop one's actionWhenFinished runs **after** hop two's `BeginSecondPick` is already live; if both hops set `Active = false` directly, Active is false through hop two's whole window (KissTicker's auto-cancel and the button toggle both dead). Fix = `targetingGeneration` counter: increment per hop, cleanup clears only if the generation is still its own. Any "chained begin + shared flag" combination must take this road.
- **Role swap belongs to the right-click path only (2026-09-10)**: `Propose(selected, target, allowRoleSwap)` — right-click passes true (About.xml promises "if the selected one cannot walk, the other comes over"), `BeginDirected` (director/ambient) always false — no swap guarantees "whoever you clicked is who goes", keeps director messages truthful, and ambient must never draft player-side pawns into initiating. `NearestWilling` additionally skips receivers with `IsPlayerControlled && Drafted`: colonists under your command do not step out of a firefight for ambient kissing.
- **Cooldown bookkeeping location (2026-09-10)**: `KissCooldown.Mark` moved from `Start()` into the initiator's stage-phase init and marks the initiator only — when reservations fail (partner taken the same tick) the job never landed, and booking early means paying a phantom 2.4-game-hour pair cooldown.
- **Stage pathing budget (2026-09-10)**: `Usable`'s last step is `CanReach` (A*); 140 radial candidates × 2 assignments worst case burns ~280 A* calls in one tick = perceptible hitch in dense ruins (prime suspect for the old "kisses then freezes for seconds" matrix item). Now failure count hitting `ReachCheckBudget=24` abandons staging for the Touch fallback — the failure path was going to fall back anyway, so it saves time without changing behavior.
- **Channel build discipline (fixed 2026-09-21)**: `MWAHBuildFlavor` (Dev/Steam/GitHub) decides whether `MWAH_DEV` exists, and the dev instrumentation class `KissTrace` was wholly wrapped in `#if MWAH_DEV` — `JobDriver_Kiss` had one `KissTrace.Clear()` line outside any #if, so **Steam / GitHub channels simply did not compile** while the default (Dev) channel stayed green and `verify-local` too (it only built the default channel). Fix = collapse the whole `#if/#else` into `KissTrace.cs` itself: the dev side is the real sampler, the release side is a same-signature shell whose every method carries `[Conditional("MWAH_DEV")]` ⇒ call sites vanish at compile time without #if noise in the performance code (instrumentation sits where performance sits). Gate 1b builds all three channels since then. Lesson: **anything conditionally compiled must ship its own release-side stand-in, and the gate must actually compile that channel**.
- **`MwahMod.Settings` is never null (2026-09-21)**: the static settings field starts as a fully defaulted instance and is wholesale replaced by `GetSettings<MwahSettings>()` in the Mod constructor. Previously six null-guards (`KissBoundary`'s structure/gate branches, `MainButtonWorker.Visible`'s `?.`/`?? true`, `KissTicker`, `KissAmbient`) coexisted with a dozen-plus direct dereferences — the null-guards protected nothing (the same decision chain dereferenced downstream anyway) and invented an unreproducible "settings not loaded" false cause. For any static state: guarantee non-null and delete every guard, or guard everywhere — never leave half a system.
- **One evaluation, one reason (2026-09-21)**: `KissUtility.BeginDirected` returns the full `KissProposal` (no longer just null), and `KissDirector.Dispatch` consumes `Allowed` / `BlockedReason` directly; `DirectPreview` was deleted — its only reason to exist was "the initiation path returns bool, so learning the reason means judging again", and `Propose`'s tail `CanReach` is A*, i.e. every rejection burned a pathfind for nothing and could even disagree with itself. The invariant (`Allowed ⇒ both pawns non-null`) lives in exactly one place: `KissProposal.TryGetPair()`.
- **Ambient dispatch is capped (2026-09-21)**: `KissAmbient` attempts at most `MaxDispatchAttemptsPerCycle = 6` real dispatches per cycle. Without the cap, a map where "nobody can kiss" (everyone cooling down, or divided by a river) would `Propose` every non-player pawn in one tick, each ending in A*. The scan start is random anyway; the cap only defers remaining chances to the next cycle without changing fairness.
- **`KissBoundary` layers no longer re-run each other (2026-09-21)**: `CanInitiate` checks only the three initiative rules (can walk, has a mouth, life stage allows it); the participation layer is checked first by the caller in order. The old `Propose` ran `Awake()/IsBurning()/IsMutant/IsInteractionBlocked` twice per pawn (the last one iterating hediffs), and that chain sits inside ambient's O(N²) candidate scan. The precondition is in the method comments: the only full-chain entries are `Propose` and `PairLooksKissable`.
- **Walk-home became its own class (2026-09-21)**: `Systems/KissReturnQueue.cs` — three jobs: `Enqueue` / `Drain` / `Reset`; the recursion cause and "why swap the list out before iterating" are in the class comment. Previously these four members sat mid-file in `KissUtility`, mixing "should they kiss / who goes" decisions with job-end bookkeeping in one 280-line file; `KissUtility` now holds only decisions and initiation. The issuing side `Request` became private (only `Drain` calls it).
- **Static state leaks across games (fixed 2026-09-10)**: `KissCooldown`'s two tables, `KissReturnQueue.Pending` (in this class since 2026-09-21; formerly `KissUtility.PendingReturns`), and `KissDirector.Active` are all static, while `TicksGame` and `thingIDNumber` restart from 0 every game ⇒ last game's cooldown `until` sentences an ID-colliding pawn to an absurdly long freeze, the return queue holds references to dead-game pawns, and stale Active triggers false pick-cancel. The reset point = `KissTicker`'s `(Game)` constructor (`Game.FillComponents` re-instantiates components at every game start/load — the constructor is the guaranteed-per-game hook). Lesson: **a static's lifetime defaults to the process, not the game session; any session-scoped static must be reset in a GameComponent constructor**.
- **What we will not do: a custom trait/xenotype kiss-value table**. Vanilla's carriers are exactly three kinds — (1) `SocialImpact` (skill + mouth/ear capacities + hats; any mod's gene statOffsets hook in automatically), (2) `nullifying*` / `required*` lists on ThoughtDef (this mod uses only this), (3) **frequency** factors like `lovinMTBFactor` / `socialFightChanceFactor`, not mood. Xenotypes (`XenotypeDef`) carry no stats at all in 1.6, and no vanilla gene touches `SocialImpact` ⇒ inventing one would be a bespoke mechanic with no precedent, neither conflicting with nor supported by the "pure entertainment, low gate, conservative rewards" stance. **If phase two wants differentiation, the right axis is relationships** (`pawn.relations` + `ThoughtDef.stages` picking stageIndex: stranger / friend / lover), which is what vanilla actually built for "what is this kiss worth".
- Settings-page auto-measure: `viewRect.height = list.CurHeight + 16f` write-back (1.6's `Listing_Standard` has **no** `BeginScrollView/EndScrollView` instance methods — do not assume). verify-local gate 9b: `RestoreDefaults` must assign every field from `Constants.*`; a new setting missing from RestoreDefaults goes red immediately. (Note: the write-back alone was insufficient — see the 2026-09-30 scrolling entry.)
- Dispatch (director/ambient) versus right-click share `Propose` but differ deliberately: swap (see above), rejection messaging (right-click posts a Message, dispatch is silent or posts afterward), `playerForced` (dispatch sets it, right-click does not).

## Commit and command practices

- Conventional Commits 1.0.0; imperative English subject, body may explain motives and trade-offs (any language, but memory files themselves are English).
- Atomic split: skeleton/metadata → gameplay code + Defs → localization → packaging tools → memory documents. Defs travel with code (splitting leaves an uncompilable middle state); localization may separate.
- Rename-style changes go in a new commit after the change; never rewrite history.
- Branch model (ruled 2026-10-04, aligned with sibling repos; branch update 2026-10-05): **atomic commits land on the current version branch** (`0.2.x` since 2026-10-05; `0.1.x` archived without release); `main` is release-only (tags must lie on main's history; release CI checks ancestry); `dev` retired (history in OBLIVIONIS 2026-10-04). Squash merge into main; history append-only.
- Never committed: `dist/`, `1.6/Assemblies/*.{dll,pdb,xml}`, `Source/**/{obj,bin}`, `About/PublishedFileId.txt`, `.idea/`, `.vs/`.
- **Scratch never inside the repo root**: verify-local's privacy gate and the pre-push audit scan the working tree — a decompiled vanilla dump left at `./.tmp-decomp/` once carried absolute local paths and broke both rituals mid-run (2026-10-05; the archive agent relocated it non-destructively). Throwaway decompilation/output goes to a sibling folder outside the repository, never inside it.
- Commands: `dotnet build Source/Mwah/Mwah.csproj -nologo`; `pwsh scripts/verify-local.ps1` (all gates); three-channel packaging `build-dev.ps1` / `pack-github.ps1 -Version v…` / `pack-steam.ps1` (packaging always builds, each channel its own flavor; pack-dev is build's alias layer). No test project; the live surface is `TODO.md`; full flow `docs/release-runbook-zh.md`.

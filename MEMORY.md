## Engineering decisions

- `AGENTS.md` is injected every session and costs context: memory protocol, non-drifting identity, hard boundaries that cause mistakes if missed, and pointers to authoritative process files — nothing volatile (directory trees, file inventories, command lines, version-folder literals, progress matrices) which belongs in this file and `TODO.md`. Structure: the five sections of UniversalSqueaker's skeleton, protocol wording sourced from US verbatim (2026-10-04).
- Ambient kissing (2026-09-02 maintainer demand "所有 pawn 都啵嘴") runs as `KissAmbient : GameComponent` timed matchmaking, **only for pawns the player cannot command** (test `KissBoundary.UnderPlayerManagement = IsPlayerControlled ∨ IsColonyAnimal`, i.e. own animals count as player-side); commandable pawns remain right-click only.
  The two paths are **independent and parallel**, meeting only at `KissUtility.Propose`: a right-click kiss spawns no follow-ups, and the timer never dispatches extra because you right-clicked. There is no "hand over to the game after the player orders".
  Consequence for own animals: vanilla `CanTakeOrder` excludes `IsColonyAnimal` (cannot be right-click-ordered) and they are also not ambient subjects ⇒ **they can only be kissed, never initiate**. To let them initiate, keep them in ambient (one predicate line).
  Reason: vanilla `FloatMenuContext` first does `RemoveAll(!CanTakeOrder)` — foreign pawns cannot even be selected; zero Harmony has no workaround.
  The original rejection of the `InteractionDef` route (covers flesh + humanlike only, conflicts with the all-pawns stance) still holds — that is why a timer replaced it; `GameComponent` is auto-instantiated by vanilla, no Def/XML/patch.
  Ambient-initiated jobs carry `playerForced = true`, otherwise the pawn's own think tree yanks it back at the next override checkpoint ("cancelled at first step").
  Three settings: `autonomousKissing` (default **off**, `Constants.AutonomousKissing=false`, third priority), `autonomousIntervalTicks` (default 250 = one chance per game hour), `autonomousRadiusCells` (default 10 cells — prevents cross-map treks turning combat into a sightseeing tour).
- A refused menu item must state the true reason: `KissProposal` carries `BlockedReason` even when `Visible=false`, echoed when a stale menu item is clicked; the reason-less path (self-kiss, already blocked by `CanSelfTarget`) says "that kiss is no longer on" instead of falsely claiming "already in the middle of a kiss".
- Director form (rewritten 2026-09-04; panelized 2026-09-22, details in `docs/vanilla-capability-boundaries.md` §Panel and resolution) = a bottom-bar button toggling the `Dialog_KissDirector` non-modal panel; map picking still runs on vanilla `Find.Targeter`, consumed by `KissDirector` in two shapes: single-hop `BeginPick` for the avatar frames and two-hop `QuickChain` for quick dispatch; dispatch goes through the public `KissDirector.Dispatch` → `KissUtility.BeginDirected`. The earlier hand-rolled `KissPick : GameComponent` capturing MouseDown + drawing a prompt bar had bugs in both versions (coordinate space, persistent window killing drawing) and was retired.
  Picking and target highlighting are fully delegated to vanilla `Targeter` (`ForPawns()` parameters, pointer-following highlight, left-click commit, right/Esc cancel) — never calling `GenUI.ThingsUnderMouse` again, never hand-rolling draw/input. Stacked-cell priority is decided inside `Targeter` by vanilla rules, identical to the right-click menu.
  Visibility follows the `directorButton` setting (default on), implemented by overriding `MainButtonWorker.Visible` (`MainButtonDef.buttonVisible` is a static XML value and cannot follow settings). When turned off mid-pick, `KissDirector` ends it (`Find.Targeter.StopTargeting`).
  Copy per the maintainer's decree: `谁要发起亲吻？` → `{PAWN} 想要和谁亲吻？` — the caption under the avatar frame and the map mouse attachment share these two keys; the cancel method (right-click / click the bar button again) does not occupy a prompt line — it lives in the button tooltip and settings description.
  Accepted cost: map picking has no "greyed button" — feasibility is reported as a message at dispatch time; the panel heart does not pre-run A* either (both sides chosen = red).
- **Never start a job synchronously inside a toil's finish action (live-proven 2026-09-04)**: `TryTakeOrderedJob` starts the job **synchronously** when the pawn is idle, and the new job's StartJob ends the old job that is mid-finish ⇒ the old job's finish action re-enters ⇒ infinite recursion within one tick. Scene of the crime: one log line repeated to Unity's fold cap of 99, `Mwah-trace.log` stalling, main thread frozen for seconds, process vanishing without "not responding", dump bottoming out in ntdll. Hence "walk home" became a queue (`KissReturnQueue.Enqueue`), drained next tick by `KissTicker.GameComponentTick`; every finish action carries an idempotency gate. **No finish action may ever call StartJob/TryTakeOrderedJob directly.**
- **Gate-exemption switch** (2026-09-04 maintainer): setting `noCooldowns` (default off) skips both the per-pawn and per-pair cooldowns; "already kissing" is never skipped — the mirror job structurally admits no third party. The maintainer's reason: the player is super-intelligence's hand and may matchmake anyone.
- **Addon layer and fate tables (reworked 2026-09-28, maintainer-set direction; 2026-09-30 namespace incident corrected)**: core is only "pawn kisses pawn"; "pawn kisses non-pawn" is an addon family (walls now, trees later) — the mover is always the pawn, initiation is one-way. **The `KissThingAddon` base class absorbed the whole pipeline** (Propose template: switch→participation→initiation→busy→cooldown→stand cell; BeginKiss/BeginDirected; FindStandCell; Pickable with fog filtering), leaving addons four things: `Active` (own switch ∧ master switch) / `Accepts` / `Scope` / `OptionLabel`; one line in the `KissThingAddons.All` registry = every path wired (right-click, director, ambient, silent invalidation, slot reclaim). Shared `MWAH_KissThing` job (one driver for the whole family; one busy-check covers all: someone kissing a wall has no time for a tree). **Silent invalidation is constitutional**: when a proposal's `Visible=false` (switch off, target gone), every entry point is mute — no greyed item, no dispatched job, no "no longer valid" message. **Fate table `MWAH_FateDef` (new Def type)**: structure in Defs, wording in translation files — per row scope/thought(nullable)/weight(relative)/narrationKey/messageKey; **empty thought + narrationKey = replace the description of an existing memory**, **empty thought + messageKey = pure message channel**. Five factory tables: **KissWall** 50 rows (five tiers × 10 narration lines, weights 40/60/50/34/16×10 ⇒ 20/30/25/17/8%); **KissPawn** 10 rows (humanlike two-person kiss narration into the mood-instance description; value/duration/SocialImpact unaffected by the table); **KissPawnMechanoid** 10 rows and **KissPawnBeast** 8 rows (mechs/animals have **no needs.mood, no thought can be granted** — a vanilla capability boundary — so they use the messageKey channel); **KissPawnMutant** 10 rows (entities = mutant shells whose mood `disableNeeds` stripped **or** any modded humanlike-without-mood race; routing discriminator `Humanlike ∨ IsMutant` so a non-humanoid mutant never falls into the animal table; 2026-10-05 maintainer ruling: **mech-equal treatment**, admission left to the gate slider, the old participation-layer `incapableOfSocialInteractions` block deleted, and **copy is body-agnostic — psychology only, zero appearance words**, since an entity may not have a humanoid form). Table emptied → fallback (wall: built-in five-tier distribution; pawn: static description / no message). **Narration into thought entries**: `MWAH_Kissed`→`Mwah.Thought_MemoryFated`, `MWAH_KissedBond`→`Mwah.Thought_MemorySocialFated` (new `IFatedNarration` contract; the settlement side recognizes the interface, not the variant) — vanilla `NeedsCardUtility.DrawThoughtGroup` reads the thought **instance's** virtual `Description` (the official opening `Thought_FoodEaten` uses), the narration key saves with the memory instance ⇒ every pawn's every memory speaks its own line, **zero patches**. Note: Thought has no `PostExposeData` (that is ThingComp's) — fields are storage, properties merely forward. **Namespace survival rule (live-proven 2026-09-30)**: the `MWAH_FateDef` class must live in the `RimWorld` namespace — a def's XML root element resolves by **short name** (`DirectXmlLoader.DefFromNode` → `GenTypes.GetTypeInAnyAssembly`, whitelist `IgnoredNamespaceNames` = RimWorld/Verse/LudeonTK/…/System); classes in the `Mwah` namespace are invisible to the loader ⇒ the whole fate table silently dropped with one ErrorOnce line; verify-local gate 6b nails this (field classes like workerClass use full names and are exempt — only root elements are affected). **Harmony grant record**: on 2026-09-28 the maintainer verbally relaxed "appropriate Harmony patches acceptable", but after full-chain verification fate/narration achieved zero patches — **the boundary in practice remains zero Harmony** (whether AGENTS.md wording changes is the maintainer's call).
- Kiss clock = **initiator's alone** (live-proven 2026-09-04; exit mechanism updated with the truce-window rework 2026-09-28): when both sides counted their own 150 ticks, whoever was processed first in the same tick hit completed=True and ended the job first, and the other side's symmetric fail check instantly kicked the initiator back to completed=False; Settle requires "initiator ∧ completed=True", so in the half of runs where the passive side finished first nobody got mood (measured: "not 100% of pawns had mood"). The passive side still **never counts down**: the old version ended the whole job via "partner dropped out ⇒ symmetric failure"; now the initiator's finished state is the in-job return leg (still inside the job) where the symmetric failure cannot catch it, so the passive side reads `PartnerDriver.completed` (or driver disappearance) and **follows into the return leg** — the exit changed from "scatter" to "walk home one after another", settlement ownership unchanged.
- **Attribution discipline (repeatedly proven in this project, cross-project)**: when the engine's authoritative output exists (translation reports, crash dumps, `FinalizeInit` self-proof logs), never stop at speculation; **never default-explain with "the user installed an old package"** (this project misjudged that way twice; both times it was our own bug); instrument lines must carry unique fields (`t=`/counters), otherwise Unity's fold-at-99 exactly hides "the same call re-entered N times".
- Kiss positioning = **fixed stage** (2026-09-03; since 2026-09-28 the search moved into `KissStage`, executed synchronously by `KissUtility.Start` before both jobs are created): a pair of left-right adjacent static cells, each walks to their own (own cell stored in the job's `TargetIndex.B`), **each job reserves only its own cell + the partner pawn** (the old form had the initiator reserve both cells; ownership split after the same-frame dual start, coverage unchanged). The immobile side is nailed to its current cell, so the walking one circles to its side — "kissing a downed pawn" therefore also gets left-right facing. The abandoned form ("passive side closes in via `PathEndMode.Touch` + active side recomputes the side cell every tick") produced front/back positioning because Touch ignores direction and the target drifted with the partner's movement; facing could then only be North/South. Bodies 2x2 and larger do not fit the model and fall back to Touch. Role recognition: `TargetIndex.C` is always the initiator, "I am not C" = passive — no more guessing from whether B was filled. **Seat-swap deadlock iron law (live-proven 2026-10-04)**: `Usable` always rejects **the other party's current cell** — after same-frame dual start, "my stage = your position, yours = mine" is a mutual wait-for-you-to-move deadlock (vanilla pathing never finishes on a cell occupied by another pawn); both burn their walk budgets and silently scatter within a second of begin (the trace never even catches a walk phase). The old serial entry (passive side departing only at lock) was structurally immune; same-frame start created it. One's own current cell remains allowed (zero-cost arrival).
- **Truce window = job lifetime** (2026-09-28 triple ruling; 10-04 added the seat-swap law): the "coexist peacefully" window for hostile kiss targets covers **approach + performance + departure** in full, with zero new primitives — job ownership natively suspends the think tree. Three pieces: (1) both jobs start on the same frame (`KissUtility.Start`); (2) the return leg lives inside the job (`KissReturn` shared toil, 1200-tick hard cap, stop-loss ends in place, queue as backstop); (3) the passive side reads the initiator's `completed` flag to follow into the return (see the kiss-clock entry). **Rulings**: no distinction between mechanoid and organic — everyone flips hostile only when the job ends; **the combat gate binds ambient only** (`KissBoundary.InCombatNow`: one of AttackMelee/AttackStatic/SocialFight) — player-issued orders (right-click / director) override everything: "if super-intelligence wants two pawns to kiss, they kiss" (same constitution as noCooldowns). **Damage self-destruct gate**: both drivers override `JobDriver.Notify_DamageTaken` (the job tracker calls it **before** the playerForced and 180-tick-cooldown gates, synchronously on the damage event itself; vanilla precedent: PredatorHunt/TendPatient), criterion `ExternalViolenceFor ∧ canInterruptJobs` ⇒ zero latency, one clock across all three paths (the dead-end of relying on `checkOverrideOnDamage` is archived in OBLIVIONIS). **The warqueen case (closed)**: spawning (`CompMechCarrier`) and firing (its turret) are both think-tree job channels, silenced together by job containment; already-spawned war urchins are independent pawns outside the pair truce. **1.6 API facts (nailed this round)**: `JobDriver` has no overridable `Cleanup` (end-of-job registration goes in a finish action); `Pawn_JobTracker.StartJob` returns **void** (compare `pawn.CurJob`); attack job names are `AttackMelee`/`AttackStatic` (old `Attack`/`Manhunt`/`Berserk` do not exist); XML root-element short names resolve only for whitelisted namespaces (see the addon entry). Old saves incompatible (0.1.0 unreleased, no compat layer).
- Logging ruling (2026-09-02 maintainer; broadcast discipline 2026-09-30; **four-rung level slider 2026-10-05**): **logs go to Player.log only**, no custom files, no ring buffers or on-demand export (KissTrace's savedata sample file is a crash bypass, not a logging subsystem); **every line carries both identities** (`doer=` and `recv=`), no cid lookups. **Broadcast discipline**: the startup banner `[MWAH] Mwah! (Every Pawn Kisses Each Other) v<identity> build=<channel> startup OK/FAILED` prints **unconditionally on both outcomes** (even at Off you must be able to tell the mod lives or died — and a dead mod must say which build died; on FAILED the exception is rethrown so vanilla records the stack). **Build identity is channel-dependent (`MwahMod.VersionString()`, mechanism copied from UniversalSqueaker): dev shows `version+full-commit-sha` (same-version builds must be tellable apart in logs — the ledger of the "packaging must build" incident), Steam and GitHub show the bare version number (the +sha is a build ledger entry, not player information)**; the same string sits in a **pinned identity row above the settings page scroll area** — vanilla's own title row only draws `SettingsCategory()` (decompiled `Dialog_ModSettings.DoWindowContents`, and injecting into it would need Harmony, a hard boundary), so the mod reserves its own 24px watermark row and a bug-report screenshot pins the build at any scroll depth. **The diagnostic surface is one setting, `diagnosticLevel` (`MwahDiag`: Off / Auto / Simple / Verbose, factory Auto), replacing the old `diagnosticLogs` bool** — Auto resolves by build channel inside `MwahLog.Level` (dev→Verbose, Steam/GitHub→Simple; the #if changes only a return value, never a member — channel discipline intact). Tier contract: **Note** (`[MWAH] note:`, Simple+) = one fate-landing line per settled kiss on every settlement path (the KissPawn narration path got its own log line closing the old GrantRow-only gap) plus all abnormal exits; **Dev** (`[MWAH] dev:`, Verbose only) = phase narration and pick generations; the KissTrace 1 Hz sampler is Verbose-only. `Warn/Error` are never gated (they are "the mod is in trouble", not diagnostic noise; muting them manufactures silent failure). The old regimes "stripped at compile time in release" (void 2026-09-30) and "single on/off switch" (void 2026-10-05) are both superseded. Design and grounds: `docs/kiss-trace-logging-design-zh.md`.
- Permissiveness = **the seven-tier `KissScope` slider** (`pairScope`, 0 free colonists only → 6 everything, factory 6). Each tier = previous ∨ one population class, both sides must be in tier, every predicate taken from vanilla (`IsFreeNonSlaveColonist`/`IsColonist`/`IsPrisoner`/`IsColony*`/`Humanlike`/`IsFlesh`/`HostileTo`). It replaced the `allowHostileTargets` and `allowMoodless` booleans (see `OBLIVIONIS.md`); tier-name keys are enum-composed, and verify-local gates reverse-check bilingual parity and range constants.
- Cooldowns (per-pawn + per-pair) are **in-session memory state**: no persistence, no tick cost, expired entries swept incidentally at settlement; resetting on load is an accepted trade (same stance as `let_me_gnaw_on_you`'s `CooldownManager`).

- **Pair settlement draws without replacement (2026-10-05 live report)**: one kiss event settling two rows from the same fate table (KissPawn narration; a moodless pair sharing one scope table, e.g. animal×animal) now excludes the first draw's row from the second roll (`KissFate.Roll(scope, exclude)`). Independent draws collide at Σp² (uniform 8-row table ≈ 1/8, measured 12.5% in simulation); a collision mirrors the same line to both participants and reads as dispatcher breakage (emu × elephant both got the pocket-sniff line). Exclusion is best-effort: a one-row table still speaks (silence is worse than repetition); different-scope pairs (animal×mech) never share a row to exclude.

- **0.2.x mood architecture rulings (maintainer, 2026-10-05)**: mood memories are **relationship-keyed slots** — each kiss partner is its own group (vanilla `GroupsWith` + per-partner label ⇒ independent full-value entries; same-partner re-kiss replaces natively via `stackLimitForSameOtherPawn=1`), and every non-pawn target class (wall today; tree/bench/machine later) is its own group. **No cross-group cap** (ruling after the mechanism was decompiled and the abuse surface was laid out: player-orchestrated stacking is accepted entertainment; vanilla's own lovemakin' thoughts cap nothing across partners either; pacing friction stays in the two cooldowns). Moodless routing becomes an **ordered scope registry** (`KissFateScopes`: first match wins, no else-catchall — an unknown creature speaks nothing rather than mech jokes). Per-addon settings live in **two dictionaries keyed by stable addon id** — `addonSwitches` (the old `wallKissing` field is gone; base class implements `Active` = master ∧ dictionary) and `addonThoughtDurations` (wall factory 0.5 game day = 30000 ticks; written as `durationTicksOverride`, so tick storage and the three-unit display stay the single authority); the settings page grew a **registry-rendered Add-ons block** inside the four-section layout (core / autonomous / addons / system), with per-addon unique numeric-field focus keys. Fate copy split into **one Keyed file per table** (`MWAH_Fate_*.xml` ×2 languages — vanilla merges the directory; gates now glob it and fail on cross-file duplicate keys). Zero migration burden by design: nothing ever shipped (0.1.x archived unreleased, 0.2.0/0.2.1 never tagged — the axis sits at 0.2.2).
- Settings lifecycle: immediate in-memory authority + 0.35 s debounced disk merge + forced flush on window close + failures keep dirty and retry in 2 s (grounds: `modding_documents/draft/modsettings-value-lifecycle-decision-tree-zh.md`).
- Duration storage unit is uniformly ticks (hard boundary). Mood duration used to store a float game-hours value `thoughtDurationGameHours` (dirty decimals hidden behind 1/4-hour quantization); on 2026-09-21 it became integer `thoughtDurationTicks` + slider `step=625` (= 1/4 game hour) quantization ⇒ every duration item now travels one road: `MwahTime.FormatTicks` emits tick / real seconds / game hours at once. `MwahTime` also deleted the reverse conversions (seconds/game-hours → ticks) — "express in another unit then convert back" is precisely where configuration drift comes from. The old Settings.xml key reads as missing ⇒ factory default; nothing ever shipped (0.1.x archived, 0.2.0 never tagged), so no compat layer (same stance as the 09-02 removal of the two legacy booleans).

- **Role swap belongs to the right-click path only (2026-09-10)**: `Propose(selected, target, allowRoleSwap)` — right-click passes true (About.xml promises "if the selected one cannot walk, the other comes over"), `BeginDirected` (director/ambient) always false — no swap guarantees "whoever you clicked is who goes", keeps director messages truthful, and ambient must never draft player-side pawns into initiating. `NearestWilling` additionally skips receivers with `IsPlayerControlled && Drafted`: colonists under your command do not step out of a firefight for ambient kissing.
- **What we will not do: a custom trait/xenotype kiss-value table**. Vanilla's carriers are exactly three kinds — (1) `SocialImpact` (skill + mouth/ear capacities + hats; any mod's gene statOffsets hook in automatically), (2) `nullifying*` / `required*` lists on ThoughtDef (this mod uses only this), (3) **frequency** factors like `lovinMTBFactor` / `socialFightChanceFactor`, not mood. Xenotypes (`XenotypeDef`) carry no stats at all in 1.6, and no vanilla gene touches `SocialImpact` ⇒ inventing one would be a bespoke mechanic with no precedent, neither conflicting with nor supported by the "pure entertainment, low gate, conservative rewards" stance. **If phase two wants differentiation, the right axis is relationships** (`pawn.relations` + `ThoughtDef.stages` picking stageIndex: stranger / friend / lover), which is what vanilla actually built for "what is this kiss worth".
- Dispatch (director/ambient) versus right-click share `Propose` but differ deliberately: swap (see above), rejection messaging (right-click posts a Message, dispatch is silent or posts afterward), `playerForced` (dispatch sets it, right-click does not).

## Commit and command practices

- Conventional Commits 1.0.0; imperative English subject; body may explain motives and trade-offs (any language, but memory files themselves are English). Atomic split: code travels with its Defs (splitting leaves an uncompilable middle state); localization may separate; rename-style changes follow as their own commit; never rewrite history.
- Branch model, release-only `main`, append-only history: `AGENTS.md` + `docs/release-runbook-zh.md` are the authorities; never-committed paths live in `.gitignore`.
- **Scratch never inside the repo root**: verify-local's privacy gate and the pre-push audit scan the working tree — a decompiled vanilla dump left at `./.tmp-decomp/` once carried absolute local paths and broke both rituals mid-run (2026-10-05; the archive agent relocated it non-destructively). Throwaway decompilation/output goes to a sibling folder outside the repository, never inside it.
- Commands: `dotnet build Source/Mwah/Mwah.csproj -nologo`; `pwsh scripts/verify-local.ps1` (all gates); three-channel packaging `build-dev.ps1` / `pack-github.ps1 -Version v…` / `pack-steam.ps1` (packaging always builds, each channel its own flavor; pack-dev is build's alias layer). No test project; the live surface is `TODO.md`; full flow `docs/release-runbook-zh.md`.

## Verification status

- Release evidence lives in `docs/release_review/` — `release-0.2.2-review-zh.md` carries the download-level asset verification, the three audit runs, and the dev-package live acceptance for the shipped 0.2.2. Offline standard remains `verify-local` fully green (its own output is the authority on gate count); live testing is the maintainer's alone; unchecked = unverified.
- The reverse key check ("defined but never referenced") is a gate worth its keep: during development it caught `Mod.cs` losing its `SettingsCategory()` override — a non-empty return is the sole condition for the settings page appearing under "Mode options", and losing it makes the entire settings surface unreachable. Think hard before deleting this check.
- Artifact shape: a dev rehearsal is a **folder dropped into `Mods/`, never an archive** — `pack-dev.ps1` produces only `dist/dev/Mwah/` and clears any stale dev zip first (a leftover must not masquerade as this round's output); `-Zip` is opt-in for callers that genuinely need an archive (CI's artifact upload). github = `dist/github/Mwah-v<tag>.zip`; steam = `dist/steam/Mwah/` directory (never zipped). The zip writer (in `stage-package.ps1`) roots entries under exactly one top-level `Mwah/` and stamps every entry with the commit's author date, so the same commit packs to a byte-identical archive (US review lessons S2/S4: contents-rooted zips scatter a loose `LoadFolders.xml` into `Mods/`; `Compress-Archive`'s mtime stamps make hashes unreproducible). Inside each package, `version.txt` = name+label / build / commit; `dist/` and all DLLs are gitignored.

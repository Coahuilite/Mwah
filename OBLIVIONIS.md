## 2026-10-06 — Settled lesson entries archived from MEMORY (memory compression)

source: MEMORY "Engineering decisions" entries dated 2026-09-04 to 2026-10-04.
reason: every lesson below is now carried by an in-code comment at its fix site (class/method docs name the incident and date) and by the gate that pins it; the MEMORY copies were pure duplication and the file had grown past its budget.
status: archived; do not re-add to MEMORY.

- **Crash attribution correction (2026-09-04, important)**: the earlier "three hard crashes on 2026-09-02 attributed to the environment (Steam overlay / Defender lazy-loading `TextShaping.dll`)" conclusion **was falsified**. The real culprit was this mod's own finish-action synchronous StartJob recursion (see the "never StartJob in a finish action" entry below). Lesson: no managed exception in `Player.log` **≠** managed innocence — deep recursion exhausts the stack and dies in native code; "was doing X when it crashed" neither convicts nor exonerates X. Triage method: `RimWorld_NativeHeapCrash_Triage_Guide_zh.md` §6.5–6.6 and `RimWorld_Mod_Silent_Failures_Engine_Contracts_zh.md`.
- **Debugger choice (measured 2026-09-03; gating moved to runtime 2026-09-30)**: dnSpy-class debuggers attach via ICorDebug, CLR-only; RimWorld runs MonoBleedingEdge ⇒ **live attach cannot see the managed stack**; dnSpy is worth keeping only for decompilation. Mono soft-debugging needs `--debugger-agent` at launch — unrealistic for an installed Steam copy. Hence the bypass sampler `KissTrace`: a background thread at 1Hz copies the phase stamps written by the main thread (begin/walk/perform/return + remaining ticks; the lock phase disappeared with the truce-window rework) into `Mwah-trace.log` in the savedata folder; main thread hangs ⇒ the file stops; crash ⇒ read the tail. Old regime: the class vanished at compile time in release builds; since 2026-09-30 it is resident in all builds, governed by the settings-page "diagnostic logs" runtime switch (off ⇒ Sample returns immediately, writes nothing).
- **Same-frame dual job start races vanilla's synchronous toil chain (fixed 2026-10-04, core feature was 100% broken)**: `Pawn_JobTracker.StartJob` runs `curDriver.ReadyForNextToil()` **at the call site** (verified by decompiling 1.6.4871, not inferred), so an `Instant` first toil (our `ToilBegin`) chains synchronously into the next toil, and `CheckCurrentToilEndOrFail` evaluates `endConditions` **before** that toil's `initAction` — and in 1.6 `Toil.AddFailCondition` writes into `endConditions`. So when `KissUtility.Start` lands the passive job first, its `ToilGotoStage` entry check reads the initiator's `CurJob` before the initiator's `StartJob` has run ⇒ both mirror jobs abort on the same frame ("partner left the kiss" misread as "partner has no job yet"). The 09-28 truce-window change planted it; live testing only exposed it 10-04. Fix = startup-frame grace: the partner-left check returns false while `TicksGame <= job.startTick` (`StartJob` sets `startTick` to the landing tick), so neither side judges the other absent until both jobs exist; real departures (death / job steal / damage break) all land on later ticks and still fire. **General law: any "is my partner still doing X" entry-time fail condition on a job started in the same frame as its mirror MUST carry a `startTick` grace — order of the two `StartJob` calls cannot fix it (whichever lands first sees the other not-yet-started).**
- Settings-page scrolling = **cross-frame cached height + single-column Begin** (live incident 2026-09-30): IMGUI fixes the scroll range at the `BeginScrollView` call, but content height is only known after drawing — "write viewRect.height back after End" writes a **local variable**, which equals never writing it, every frame (the 2026-09-10 auto-measure was exactly this broken fix; the scrollbar was permanently unusable). Where overflow actually goes: `Listing_Standard`'s **automatic column switch** — when `maxRect.height` cannot fit, `NextColumn()` paints the tail entries and "restore defaults" outside the window's right edge (live screenshot: vertical glyph ghosts outside the window + a floating orange button). Correct fix, two parts: (1) cache the content height in a **field** across frames (from frame 2 the scroll range is true; the first frame at worst scrolls one screen short); (2) hand `list.Begin` a near-infinite height so column-switching never fires and all overflow goes to scrolling. Vanilla `Dialog_ModSettings` passes `inRect` straight to `DoSettingsWindowContents` with **no outer scroll view** — nested scrolling is not an excuse.
- **Chained-Targeting cleanup race (fixed 2026-09-10)**: vanilla event order is action → StopTargeting → actionWhenFinished, so hop one's actionWhenFinished runs **after** hop two's `BeginSecondPick` is already live; if both hops set `Active = false` directly, Active is false through hop two's whole window (KissTicker's auto-cancel and the button toggle both dead). Fix = `targetingGeneration` counter: increment per hop, cleanup clears only if the generation is still its own. Any "chained begin + shared flag" combination must take this road.
- **Cooldown bookkeeping location (2026-09-10)**: `KissCooldown.Mark` moved from `Start()` into the initiator's stage-phase init and marks the initiator only — when reservations fail (partner taken the same tick) the job never landed, and booking early means paying a phantom 2.4-game-hour pair cooldown.
- **Stage pathing budget (2026-09-10)**: `Usable`'s last step is `CanReach` (A*); 140 radial candidates × 2 assignments worst case burns ~280 A* calls in one tick = perceptible hitch in dense ruins (prime suspect for the old "kisses then freezes for seconds" matrix item). Now failure count hitting `ReachCheckBudget=24` abandons staging for the Touch fallback — the failure path was going to fall back anyway, so it saves time without changing behavior.
- **Channel build discipline (fixed 2026-09-21)**: `MWAHBuildFlavor` (Dev/Steam/GitHub) decides whether `MWAH_DEV` exists, and the dev instrumentation class `KissTrace` was wholly wrapped in `#if MWAH_DEV` — `JobDriver_Kiss` had one `KissTrace.Clear()` line outside any #if, so **Steam / GitHub channels simply did not compile** while the default (Dev) channel stayed green and `verify-local` too (it only built the default channel). Fix = collapse the whole `#if/#else` into `KissTrace.cs` itself: the dev side is the real sampler, the release side is a same-signature shell whose every method carries `[Conditional("MWAH_DEV")]` ⇒ call sites vanish at compile time without #if noise in the performance code (instrumentation sits where performance sits). Gate 1b builds all three channels since then. Lesson: **anything conditionally compiled must ship its own release-side stand-in, and the gate must actually compile that channel**.
- **`MwahMod.Settings` is never null (2026-09-21)**: the static settings field starts as a fully defaulted instance and is wholesale replaced by `GetSettings<MwahSettings>()` in the Mod constructor. Previously six null-guards (`KissBoundary`'s structure/gate branches, `MainButtonWorker.Visible`'s `?.`/`?? true`, `KissTicker`, `KissAmbient`) coexisted with a dozen-plus direct dereferences — the null-guards protected nothing (the same decision chain dereferenced downstream anyway) and invented an unreproducible "settings not loaded" false cause. For any static state: guarantee non-null and delete every guard, or guard everywhere — never leave half a system.
- **One evaluation, one reason (2026-09-21)**: `KissUtility.BeginDirected` returns the full `KissProposal` (no longer just null), and `KissDirector.Dispatch` consumes `Allowed` / `BlockedReason` directly; `DirectPreview` was deleted — its only reason to exist was "the initiation path returns bool, so learning the reason means judging again", and `Propose`'s tail `CanReach` is A*, i.e. every rejection burned a pathfind for nothing and could even disagree with itself. The invariant (`Allowed ⇒ both pawns non-null`) lives in exactly one place: `KissProposal.TryGetPair()`.
- **Ambient dispatch is capped (2026-09-21)**: `KissAmbient` attempts at most `MaxDispatchAttemptsPerCycle = 6` real dispatches per cycle. Without the cap, a map where "nobody can kiss" (everyone cooling down, or divided by a river) would `Propose` every non-player pawn in one tick, each ending in A*. The scan start is random anyway; the cap only defers remaining chances to the next cycle without changing fairness.
- **`KissBoundary` layers no longer re-run each other (2026-09-21)**: `CanInitiate` checks only the three initiative rules (can walk, has a mouth, life stage allows it); the participation layer is checked first by the caller in order. The old `Propose` ran `Awake()/IsBurning()/IsMutant/IsInteractionBlocked` twice per pawn (the last one iterating hediffs), and that chain sits inside ambient's O(N²) candidate scan. The precondition is in the method comments: the only full-chain entries are `Propose` and `PairLooksKissable`.
- **Walk-home became its own class (2026-09-21)**: `Systems/KissReturnQueue.cs` — three jobs: `Enqueue` / `Drain` / `Reset`; the recursion cause and "why swap the list out before iterating" are in the class comment. Previously these four members sat mid-file in `KissUtility`, mixing "should they kiss / who goes" decisions with job-end bookkeeping in one 280-line file; `KissUtility` now holds only decisions and initiation. The issuing side `Request` became private (only `Drain` calls it).
- **Static state leaks across games (fixed 2026-09-10)**: `KissCooldown`'s two tables, `KissReturnQueue.Pending` (in this class since 2026-09-21; formerly `KissUtility.PendingReturns`), and `KissDirector.Active` are all static, while `TicksGame` and `thingIDNumber` restart from 0 every game ⇒ last game's cooldown `until` sentences an ID-colliding pawn to an absurdly long freeze, the return queue holds references to dead-game pawns, and stale Active triggers false pick-cancel. The reset point = `KissTicker`'s `(Game)` constructor (`Game.FillComponents` re-instantiates components at every game start/load — the constructor is the guaranteed-per-game hook). Lesson: **a static's lifetime defaults to the process, not the game session; any session-scoped static must be reset in a GameComponent constructor**.
- Settings-page auto-measure: `viewRect.height = list.CurHeight + 16f` write-back (1.6's `Listing_Standard` has **no** `BeginScrollView/EndScrollView` instance methods — do not assume). verify-local gate 9b: `RestoreDefaults` must assign every field from `Constants.*`; a new setting missing from RestoreDefaults goes red immediately. (Note: the write-back alone was insufficient — see the 2026-09-30 scrolling entry.)
